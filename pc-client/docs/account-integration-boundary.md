# 用户系统接入边界

当前阶段已启用邮箱验证码注册、登录、资料维护、邮箱和手机号修改、密码修改、设备会话、统一提醒、收藏与喜欢。PC 客户端不保存论坛管理员、数据库凭据或社区密码。

## 已确定

- 身份服务：AI Hub 自有 `identity-community` 服务。
- 登录标识：不可变用户名或已验证邮箱；手机号当前作为联系方式。
- 验证通道：本地 Mailpit 邮件链路；生产环境必须替换为正式邮件服务。
- 用户主键：不可变 UUID；Flarum 使用不可变用户名进行当前映射。
- 会话策略：15 分钟访问令牌、30 天可轮换刷新会话、退出和设备撤销。
- 私有数据：联系方式和账号提醒由身份服务持有；社区提醒、关注和喜欢由 Flarum 持有，身份服务只在请求时聚合。

## 客户端边界

- 密码和验证码只提交给身份服务，不写入目录 CMS。
- 长期刷新凭据进入 Windows 安全存储，不写入普通配置文件或日志。
- 主进程负责安全存储与内嵌社区会话创建，渲染进程只获取最小化用户快照。
- Flarum 登录由服务端签发一次性跳转凭据，客户端不持有论坛管理员密钥。
- 社区容器使用独立分区且禁用 Node.js、preload 和权限申请，不能读取 PC 会话凭据。
- 用户名作为社区映射键保持不可变；昵称、头像和个签属于可修改的社区资料。
- PC 只调用统一个人中心接口；Flarum 内网桥不向客户端暴露共享密钥或其他用户数据。

## 已完成验收

- 注册、登录、刷新、退出和撤销设备经过真实本地服务验证。
- 验证码具备限流、过期、重放防护和失败次数限制。
- 邮箱换绑需要当前密码与新邮箱验证码。
- 修改密码后其他设备会话被撤销。
- PC 与社区映射不会产生第二套密码或重复注册。
- 内嵌社区只允许精确来源和单次 handoff。
- 账号提醒与 Flarum 原生提醒、关注、喜欢通过同一接口进入 PC 个人中心。
