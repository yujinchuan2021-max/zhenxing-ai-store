# 受管桌面产品缺少生命周期仍可通过审批

日期：2026-08-04

## 现象与证据

在继续扩充 Windows 桌面一键安装前审计本地合同，31 个受管桌面产品都被后台标记为“已审核”，但只有 7 个产品能从 `getDesktopLifecycle()` 取得非空合同。其余 24 个产品缺少更新归属、更新策略、数据保留和安装器产品身份，独立审批仍会把 `null desktopLifecycle` 计入哈希并放行。

## 根因

审批只验证“当前注册项与已保存哈希一致”，没有先验证受管桌面注册项是否包含完整生命周期。哈希能够证明空值没有被改动，却不能证明空值满足审核门槛。

## 排除的错误处理

- 不能继续把新产品加入白名单后再补资料；这会扩大错误的“已审核”集合。
- 不能只在后台把产品改成待审核；客户端本地合同仍可被其他入口读取。
- 不能用签名者或固定 SHA-256 代替安装器 PE/VersionInfo、更新归属和用户数据保留合同。

## 修复

- `buildProductIntakeDossier()` 对 `managed-installer` 强制要求桌面适配器、更新归属、更新策略、HTTPS 最新来源、数据保留、安装器类型以及真实下载文件的 PE 架构和 VersionInfo。
- 缺少任一字段时资料卡直接无效，产品不能获得客户端执行许可。
- Windows 扩展桌面的生命周期与下载身份合并到同一产品白名单定义，由生命周期模块只读投影，避免两个文件重复填写相同身份。
- 现有缺失产品必须逐项补证并重新计算独立审批哈希；证据不足的产品退回官方下载入口。

## 自动验证

- 新回归测试证明：即使攻击者为缺失生命周期的注册项重新计算匹配哈希，资料卡仍被拒绝。
- Jan、Visual Studio Code 和 Zed 改为单一合同来源后，原审批哈希保持不变，生命周期与安装器身份测试通过。
- 全量产品收口完成后仍需运行产品资料卡、认证、目录、下载源、安装器身份和封装客户端门禁。

## 剩余人工验收

自动审批门禁不会运行第三方安装器。每款恢复为“已审核”的产品仍需在用户日常 Windows 账户分别完成安装、首次启动、更新、卸载和数据保留验收，之后才能标记“已实机验收”。

## 防复发门禁

“审批哈希匹配”只证明合同未漂移，不证明合同完整。所有本地可执行产品必须先通过结构完整性门禁，再计算和核对独立审批；新增字段不得使用 `null`、空对象或后台展示值绕过。
