# 产品安装包下载任务生命周期

## 用户目标

PC 客户端直接下载白名单内的官方安装包时，用户需要能看懂并控制整个任务，而不是只能看到一个临时进度条：

- 下载过程中可以明确暂停。
- 网络中断必须显示为失败，不能冒充用户主动暂停。
- 失败或暂停后可以继续断点。
- 客户端重启后仍能恢复任务和日志。
- 取消必须二次确认，并且只清理当前产品受控的 `.part` 文件。
- 不增加新页面或左侧导航，所有状态仍放在厂商产品卡片内。

## 原问题

此前下载过程主要依赖渲染页面内的临时状态：

1. 页面刷新或客户端重启后，正在下载的状态和操作上下文会丢失。
2. 用户暂停与网络失败共用相近的表现，无法判断应该等待、继续还是重试。
3. 没有稳定的 attempt 身份，旧下载尝试的迟到事件可能覆盖新重试。
4. 取消、流刚好结束和最终文件落盘同时发生时，存在卡在“正在取消”的竞态。
5. 断点记录依赖当前设置中的下载目录；用户改目录后，旧盘的大文件可能失去管理。
6. 断点删除失败、系统时钟回拨或本地 JSON 顶层损坏时，恢复链路缺少明确降级。

## 设计

### 任务状态由主进程拥有

渲染页面只发送白名单产品 ID。主进程负责读取固定下载方案、创建 attempt、下载、持久化和广播任务快照，不接受页面传入任意 URL 或文件名。

任务使用以下状态：

- `starting`
- `downloading`
- `pausing`
- `paused`
- `failed`
- `canceling`
- `canceled`
- `completed`

每个快照包含 `attemptId`、递增 `revision`、进度、错误、校验后文件证据和最多 40 条状态日志。重试创建新的 attempt；旧 attempt 的迟到事件会被状态机拒绝。

### 可恢复持久化

- 任务快照、断点记录和完成记录使用临时文件加原子重命名写入。
- 启动时对每个任务单独恢复；单个损坏记录不会阻断其他产品。
- 崩溃时遗留的活动任务恢复为可理解的暂停状态。
- 系统时钟回拨时，`updatedAt` 保持单调，避免写出下次无法读取的快照。
- 只有普通对象形式的 JSON 顶层记录会被接受。

### 暂停、失败与取消严格区分

- 暂停是用户意图，流关闭后保留可信非零断点并进入 `paused`。
- 网络或磁盘错误进入 `failed`，并根据真实 `.part` 文件决定能否继续。
- 取消采用 `download < pause < cancel` 的单向意图优先级，暂停不能覆盖已确认的取消。
- 下载流关闭后、最终重命名前以及完成记录写入前都会再次检查取消。
- 断点删除失败时不会误报已取消；任务进入明确、可重试的清理失败状态并保留记录。
- 断点记录保存不可变的规范下载根目录。修改设置中的下载目录后，旧任务仍能在原受控位置继续或清理。

### 完成证据

只有固定白名单、最终域名、文件边界、SHA-256 和 Authenticode 签发者策略都通过后，安装包才能进入后续“点击安装”流程。打开安装器仍不等于安装成功。

如果启动恢复时遇到“任务停在取消中，但可信完成记录已经原子落盘”，只允许专用的恢复事件依据完成证据收敛到 `completed`；实时取消路径不能直接越过状态机完成。

## 产品卡片表现

- 下载中：显示百分比、已下载/总大小、速度、剩余时间、下载磁盘空间和安装空间建议，并提供“暂停”“取消任务”。
- 已暂停：显示已保留数据量，并提供“继续下载”“取消任务”。
- 下载失败：显示真实错误；可续传时提供“继续下载”，同时保留取消和更换下载位置。
- 任务记录：在当前产品卡片中折叠展示 attempt 次数和最近状态，不新增任务中心页面。
- 已取消：清除下载状态，回到“下载安装包”。

## 自动化验证

- 纯状态机覆盖首次下载、进度、暂停、失败、取消、重试、完成、旧 attempt 拒绝、日志上限、损坏恢复和时钟回拨。
- 主进程可靠性辅助逻辑覆盖意图优先级、损坏 JSON、断点清理结果、不可变下载根目录和恢复决策。
- Playwright 覆盖开始下载、暂停、继续、模拟网络中断、再次重试、旧事件注入、刷新恢复和最终取消。
- 1080、1180、1440 三档窗口验证下载区域无横向溢出，下载状态最小字号为 13px。

## 完成边界与位置切换补充

- 网络流已经完整读完、写入流关闭且字节数匹配时，以当前 attempt 的完成结果为准；此时到达的暂停或取消意图不会把已经完成的文件错误地留在中间态。
- 若可信断点的 `.part` 文件已经等于已知总大小，继续任务时不再发出无意义的 Range EOF 请求，而是在本地重新检查文件边界、计算 SHA-256，并原子晋升为最终文件。
- 完成记录原子写入成功就是不可逆提交点；此后的断点记录清理只做尽力清理，失败不得回滚或删除已经验证完成的最终文件。
- 暂停或失败后保留两个明确动作：“继续原位置下载”沿用原断点；“更换位置并重新下载”先让用户选择目录，再经取消确认清理旧任务并从新位置开始。
- 目录选择对话框取消和重新选择当前目录是两个不同结果，前者不得意外触发任务取消或重启。

## 剩余用户验收

自动化没有为了本次状态机回归再次下载完整的 Ollama 大型安装包。最终仍需在用户当前网络、代理和真实下载目录中确认一次暂停、继续、取消及重启恢复；不能用浏览器模拟代替这一步。
