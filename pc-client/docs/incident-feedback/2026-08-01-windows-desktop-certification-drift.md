# Windows 桌面产品认证与目录漂移

日期：2026-08-01

## 用户可见问题

桌面产品数量增加后，部分目录名称、版本文件名和实际厂商发布已经漂移；GPT4All 的卸载器类型、OpenClaw 的静默卸载行为以及 NVIDIA AI Workbench 的环境依赖也与产品真实流程不一致。原有“存在白名单即已审核”的展示无法区分代码审核和真实设备验收。

## 根因

- 产品审核哈希只覆盖注册与下载，未覆盖真实桌面适配器和生命周期策略。
- 后台签名目录可启停产品，但 IPC 安装入口没有再次核对 `install` 能力。
- 缺少可追溯的待审核、已审核、已实机验收三态与追加式历史。
- 产品资料依赖人工快照，没有把来源复核结果与本地执行契约一起收口。

## 修复

- 审核哈希现在包含桌面适配器、检测身份、签名规则、卸载规则和生命周期策略。
- 新安装在 IPC 边界重新读取最新签名目录，并要求该产品仍具有 `install` 能力；产品停用不妨碍管理或卸载已安装实例。
- 后台产品编辑页加入三态认证和七项实机验收记录；待审核产品不能发布安装能力。
- 更新 Cursor 3.14.7、Kimi Work 3.1.6、千问 3.7.5.145 和 WorkBuddy 5.3.8 的已审核包身份。
- 修正 TRAE Work、Qoder/CodeBuddy 文件名、GPT4All Qt 卸载器、OpenClaw 交互式卸载、NVIDIA 可选本地环境和多个过期产品描述。
- 将依赖实时后台目录的 Electron 布局验收移到新版后台服务切换成功后执行。此前它在发布事务开始前运行，旧后台会读取新版本 bind-mounted 目录并拒绝新策略，导致发布无法进入后台升级阶段；现在失败仍处于可回滚事务内，不会形成版本互锁。

## 验证边界

自动化验证覆盖状态机、历史、执行契约失效、后台能力撤销、目录源可达性和发布门禁。它不会运行第三方安装器，也不能替代用户日常 Windows 账户下的安装、首次打开、厂商更新、卸载和数据保留验收。真实结果必须在后台逐产品记录后，状态才可显示为“已实机验收”。
