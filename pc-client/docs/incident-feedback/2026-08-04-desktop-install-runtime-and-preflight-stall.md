# 桌面产品下载、打开与任务状态收敛

## 用户现象

- Msty Go 已弹出厂商安装程序，但枕星 AI 仍等待后续安装结果，状态没有自然结束。
- Stability Matrix 安装失败并提示 `spawn C:\WINDOWS\System32\powershell.exe ENOENT`；取消后任务仍显示进行中，遗留的临时文件也没有自动清理。
- Audacity 点击安装后长时间停留在“准备中”。
- 已失败、已取消或本地文件被用户删除的旧下载任务仍留在任务中心，无法删除，也无法重新开始一次干净的下载。

## 根因

1. **桌面安装职责过重。** 下载完成后，客户端继续执行哈希、签名、安装包身份和版本校验，还试图监控厂商安装器的退出与安装结果。厂商安装流程、UAC、许可协议和安装选项并不由枕星 AI 控制，这些步骤让简单的“下载并打开”变成了容易阻塞的长事务。
2. **Msty Go 生命周期模型错误。** 需要用户操作的厂商安装向导被当作可持续追踪的安装任务。安装器已经打开后，客户端仍等待或恢复监控，不能可靠区分用户完成、取消、关闭和厂商启动器派生子进程等情况。
3. **Stability Matrix 便携安装事务不能跨重启恢复。** 解压流程错误地假定 PowerShell 位于 `C:\WINDOWS\System32\powershell.exe`；中断后的 `.pending-*` 文件和事务又被恢复为外部安装器监控任务，最终停在 `monitoring/unknown`。取消动作只改变了表面状态，没有完整删除持久任务和临时文件。
4. **Audacity 在开始安装前做了重复、串行的库存检测。** 渲染层和主进程重复预检，Winget、Windows Apps 与注册表库存扫描占用准备阶段；安装调用还把厂商流程绑定在一次 IPC 响应中，所以界面长期显示“准备中”。
5. **磁盘、持久任务与界面缓存没有统一收敛。** 失败或取消任务仍保留在持久存储中；用户在资源管理器中删除已下载文件后，刷新流程把它转成永久的“文件缺失”失败，而不是清除旧记录并恢复“一键下载”。

## 用户确认的新策略

### 桌面产品

- 已配置厂商直链的桌面产品，初始操作统一显示“**一键下载**”。
- 尚未配置稳定直链的桌面产品显示“**前往官网下载**”，直接打开厂商下载页；不得回退到 Winget 或其他包管理器替用户安装。
- 下载完成后显示“**点击安装**”，不自动启动任何程序。
- `EXE`、`MSI`、`MSIX`：点击安装时直接打开已经下载的安装包，后续许可协议、UAC、安装目录和安装选项由用户在厂商安装程序中处理。
- `ZIP`：点击安装时直接打开压缩包，不由枕星 AI 解压、复制文件或判断哪个程序应该运行。
- 不做哈希、签名、发布者身份、安装包身份或版本校验。
- 不监控厂商安装器进程，不自动判断厂商安装流程是否完成，也不把“安装器已打开”描述为“产品已安装”。
- 下载任务只负责把文件完整写入受管下载目录；打开前仅保留本地文件、路径和扩展名等基础安全检查，不做安装包内容或真实性审核。

### 下载源

- 优先使用厂商官方源。
- 只有官方源连接失败，或在首字节等待窗口内始终没有收到任何数据时，才尝试后台配置的镜像源。
- 一旦收到首段有效数据，即认为下载已经开始；后续即使速度很慢也继续等待，不因下载速度或传输间隔切换镜像。
- 镜像只是失败兜底，不进行测速竞赛，也不因用户是否使用 Clash、VPN 或其他代理而预先改写系统网络策略。

### CLI、Agent 与运行环境

- 本次减法只适用于桌面安装包。
- CLI 和 Agent 继续使用“一键部署”，由各自固定的客户端模块执行受控命令、依赖检测、安装、启动和卸载。
- Node.js、Python、Git、WSL 等运行环境继续由环境模块自动检测并按批准策略安装。

## 状态收敛规则

- 用户取消下载后，任务必须立即从进行中列表和持久存储中移除；残留的本次临时文件一并清理。
- 失败任务必须允许直接删除，并在删除后恢复可重新下载状态。
- 已完成下载对应的本地文件如果被用户删除，刷新状态时应清除失效记录并恢复“一键下载”，不得制造永久失败任务。
- 客户端重启时，不得把旧的便携解压事务恢复为厂商安装器监控任务；只清理能够精确归属本产品、本次事务的 `.pending-*` 文件，不触碰用户数据或无关文件。
- 同一产品的新任务开始前应收敛旧的失败、取消、文件缺失和遗留监控状态，避免同一产品同时显示互相冲突的状态。

## 回归验收项

### 自动回归

- 桌面产品无本地包时显示“一键下载”；下载完成后显示“点击安装”，且不会自动打开文件。
- `EXE`、`MSI`、`MSIX` 和 `ZIP` 都通过系统默认方式直接打开；桌面流程不创建安装监控任务，也不调用哈希、签名、身份或版本校验。
- 官方源连接失败或首字节超时可以切换到已配置镜像；收到首字节后，即使后续传输缓慢也不会触发速度超时或切换源。
- 下载取消后，界面任务、持久任务和本次临时文件同步消失。
- 失败任务可以删除；本地已下载文件被外部删除后，旧记录自动清除并恢复“一键下载”。
- 重启时可以清理精确匹配的便携事务临时文件，不删除产品数据目录或无关文件。
- CLI、Agent 和运行环境仍进入原有自动部署模块，不被桌面下载策略降级为仅打开文件。

### 真实 Windows 桌面验收

- **Msty Go：** 一键下载完成后不自动启动；点击安装只打开厂商安装器，枕星 AI 不再持续等待厂商向导结果。
- **Stability Matrix：** 下载完成后点击安装直接打开下载文件；旧的 `monitoring/unknown` 任务和 `.pending-*` 残留可以清除，取消后可以立即重新下载。
- **Audacity：** 点击“前往官网下载”直接打开厂商 Windows 下载页，不再调用 Winget，也不再因安装前库存扫描长期停在“准备中”。后续录入稳定官方直链后，再自然升级为“一键下载 → 点击安装”。
- **旧任务：** 失败任务可删除，取消任务立即消失；手动删除下载文件后刷新，产品恢复“一键下载”。

自动测试只能证明客户端状态机和调用边界符合策略，不能替代第三方文件在真实 Windows 桌面上的用户点击验收。

## 防复发门禁

- 桌面产品不得复用 CLI、Agent 或运行环境的自动部署流程。
- 没有已配置直链的桌面产品不得回退到包管理器自动安装，只能打开厂商下载页。
- 桌面下载完成事件不得自动调用安装入口。
- 桌面安装入口只负责打开当前产品的受管下载文件，不得重新引入安装包内容校验、便携解压安装、厂商进程监控或安装结果轮询。
- 连接和首字节失败可以触发镜像兜底；首字节之后禁止以下载慢为由中断或切源。
- 任务删除、取消、文件缺失和重启恢复都必须同时收敛内存状态、持久状态、界面缓存与可精确归属的临时文件。
- CLI、Agent 和运行环境的一键自动部署边界必须通过独立回归测试固定，避免桌面策略误伤。
