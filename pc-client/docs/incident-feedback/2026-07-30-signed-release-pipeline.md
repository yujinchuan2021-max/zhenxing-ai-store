# AI Hub 签名发布与灰度更新

## 原问题

旧后台发布会覆盖单一 `catalog-v1.json`，客户端只做可选 SHA-256。固定摘要会阻止后台持续更新，不固定摘要又无法证明发布者身份；缓存也没有签名复核、来源绑定或版本防回退。更新入口只固定下载 origin，没有签名、安装包摘要、文件大小或稳定灰度。

## 根因

内容校验、发布身份、发布历史和客户端选择被混在一个可变 URL 中。SHA-256 只能证明内容没有意外变化，不能证明谁发布了内容，也不能阻止服务器重放一个仍然有效的旧版本。

## 修复

- 发布模块生成连续 `catalogVersion`、不可变 release 文件、Ed25519 签名和原子活动指针。
- 草稿保存使用 revision CAS；旧管理页面不能静默覆盖新草稿。
- 回滚不会把指针退回旧序号，而是以旧内容生成更高的新版本。
- 客户端内置发布公钥，只接受签名有效、目录摘要匹配、来源固定且不低于已接受最高版本的 release。
- 每台客户端只生成匿名随机 `clientId`，以签名覆盖的 salt 和比例做确定性灰度；不读取硬件或账号标识。
- 签名目录缓存每次读取都重新验签，并与精确 release URL 绑定；远程失败只回退最后一次已验证缓存或内置目录。
- 签名更新清单固定 Windows x64、stable/beta、HTTPS origin、SHA-256、文件大小、说明和灰度；检查失败立即清空上一次 offer，下载入口十分钟后过期且只消费一次。
- 远程 JSON 使用流式硬上限并检查 Content-Type，跨固定 origin 的重定向被拒绝。

## 密钥边界

本机开发后台首次启动会在 `admin/data/catalog-signing-private.pem` 生成仅供开发的 Ed25519 私钥，该路径已忽略；也可通过 `AIHUB_CATALOG_SIGNING_PRIVATE_KEY` 注入外部私钥。客户端和发布文件只包含公钥。生产私钥必须放在 CI/KMS/离线签名环境，不能提交仓库或打入安装包。Ed25519 内容签名不能替代 Windows Authenticode 代码签名。

## 验证门禁

- 签名内容、密钥 ID、签名或 payload 任一篡改必须失败。
- 灰度 0%/100% 和固定客户端重复计算必须稳定。
- 草稿冲突返回 409；发布或活动指针写入失败不能切换旧版本。
- 发布历史不可变；回滚生成更高版本。
- 更新版本、平台、架构、下载 origin、摘要、大小和签名必须全部通过。
- 最终 ASAR 必须包含公钥验证模块，且不得包含 `PRIVATE KEY`、后台数据、草稿或发布历史。

## 尚需生产验收

正式 HTTPS 目录域名、下载域名、生产 Ed25519 私钥与 Windows 代码签名证书尚未提供，因此生产 channel 保持安全禁用。取得这些外部资源后才能开启公网目录和真实更新下载。
