# 安装验证在客户端重启后恢复

## 用户现象

厂商安装程序已经由 AI Hub 打开，产品卡片也进入“正在自动检测安装结果”，但关闭并重新打开客户端后，页面会退回“点击安装”。用户容易再次启动同一个安装程序。

## 原因

原来的安装监控由 React 页面内的 `AbortController` 和临时状态拥有：

1. 页面卸载时会主动取消轮询。
2. 主进程没有保存“正在等待安装验证”的会话。
3. 启动恢复只读取下载任务；一个已完成下载会被直接映射为“已下载”。
4. 迟到的下载完成事件也可能覆盖已经恢复的安装验证状态。

因此该问题是确定性的状态所有权错误，不是偶发的按钮或网络问题。

## 修复

### 主进程拥有持久验证任务

- 可信安装包通过 SHA-256、Authenticode、签发者检查和两秒启动观察后，主进程创建验证任务。
- 任务写入 `desktop-install-verifications.json`，使用临时文件加原子重命名；落盘成功后才更新内存并广播。
- 页面只读取任务快照、请求立即检测和消费事件，不再自己运行十分钟轮询。
- 每个任务包含 `verificationId`、递增 `revision`、原始 `startedAt`、绝对 `deadlineAt`、检测次数和最近 Windows 证据。

### 重启恢复与优先级

启动恢复固定使用：

```text
可信已安装证据 > 活动安装验证 > 已完成下载 > 可下载
```

- 重启后沿用原验证身份和原十分钟截止时间，不重新赠送十分钟。
- `monitoring` 与 `timed-out` 任务都会先立即扫描一次；用户在客户端关闭期间完成安装，也能直接收敛为“已安装”。
- 安装成功事件到达后删除已经完成的验证任务；若页面当时尚未监听，下一次启动仍会重新扫描 Windows 可信安装证据。
- 页面按 `verificationId + revision` 拒绝旧快照；迟到的下载事件不能把“正在检测”或“已安装”降级成“已下载”。
- 活动验证存在时再次点击安装，不会重复启动安装程序。

### 故障边界

- 单个损坏、未知产品、非法时间顺序或超长截止时间的记录只会清理自身，不阻断其他产品。
- 系统时钟回拨时，除绝对截止时间外还使用最多 120 次检测兜底，避免任务永久停在检测中。
- 后台检测的持久化失败会保留最后一个已落盘快照并安全重试，不产生未处理 Promise rejection。
- 清洗损坏记录时写盘失败不会拖垮 Electron 主进程。
- 手动“立即检测”携带当前 `verificationId`，旧页面不能推动新安装会话。

## 验收边界

自动化页面刷新和纯状态控制器重建证明了恢复协议，但不等同于用户机器上真实运行厂商安装向导后重启 AI Hub 的验收。安装任务只在安装器通过两秒启动观察后写入；若 AI Hub 恰好在这两秒内被强制终止，仍可能没有恢复记录。真实 Comfy/Ollama 安装完成、客户端重启和 Windows 注册信息仍需用户使用新版安装包确认。
