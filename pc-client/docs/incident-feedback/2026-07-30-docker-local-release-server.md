# Docker 本地发布服务反馈闭环

## 用户反馈

当前没有真实服务器，但本机有 Docker，要求直接运行并完成整个阶段；同时客户端下载更新后应直接调起安装器，不能跳转官网。

## 根因

原本地链路只有静态 Caddy，后台仍依赖宿主机进程，发布目录不可原子切换，也没有备份恢复。客户端更新按钮只调用外部浏览器，未复用已有的断点下载和完整性校验能力。部分验收脚本还读取旧的 `deployment/local/public`，存在对旧发布包产生假阳性的风险。

## 修复

- 后台和 HTTPS 发布服务均纳入 Docker Compose。
- 发布内容统一从 `deployment/local/runtime/current/public` 读取。
- 增加发布包校验、staging 激活、自动/手工备份、历史列表和安全恢复。
- Caddy 使用显式路径白名单，只读挂载当前发布目录。
- 修正所有本地验收脚本，只验证当前运行版本。
- 客户端更新改为下载、断点续传、固定完整 HTTPS origin、大小与 SHA-256 双重校验、用户确认后启动安装器。
- 更新失败不会启动安装器；校验失败的最终 EXE 会被清除，网络失败保留安全的 `.part` 供续传。

## 安全边界

- 后台只能调整展示数据和已批准策略参数，不能下发任意命令。
- 可自动安装的产品仍由客户端本地白名单批准。
- 恢复能力只提供宿主机 CLI，不开放 HTTP 恢复端点。
- 本地开发签名密钥不进入发布目录、镜像和客户端。
- 自动化不会替代真实用户点击 Windows 安装向导的最终验收。

## 验证

- 单元测试覆盖发布激活、同秒备份、恢复、路径穿越、篡改拒绝、私钥泄漏扫描，以及更新来源、端口、文件名、大小和 SHA-256。
- Docker 验收覆盖健康状态、回环端口、只读根文件系统、权限裁剪、TLS、Range、完整下载以及未批准路径 404。
- 客户端构建和本地验收包继续独立验证；未把浏览器演示或自动化测试标记为用户机器安装成功。
