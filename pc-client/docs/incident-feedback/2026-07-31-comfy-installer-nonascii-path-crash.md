# Comfy 安装器从非 ASCII 路径启动后崩溃

## 现象

用户点击 Comfy Desktop 安装后没有看到安装器，产品卡却持续显示正在检测安装。

## 真实设备证据

- 下载记录指向 `D:\文件\Comfy-Desktop-Setup-x64.exe`。
- 文件来自客户端批准的 Comfy 官方下载源。
- 文件大小、SHA-256 和 Authenticode 签名全部有效。
- 文件产品版本为 `1.0.33`，签发者为 `Drip Artificial Inc`。
- Windows Application Error 事件 1000 记录安装器发生 `APPCRASH`：
  - 异常代码 `0xc0000005`；
  - 故障模块为安装器临时释放的 `System.dll`；
  - 故障路径与 AI Hub 打开的安装包完全一致。
- 同一文件复制到
  `C:\Users\yujin\AppData\Local\AIHub\InstallerLaunch\` 后能够显示
  “Comfy Desktop 安装”窗口，五秒内没有崩溃事件。

## 根因

厂商 NSIS 安装器的旧插件不能在这台 Windows 上从含非 ASCII 字符的路径可靠
启动。客户端原先直接从用户下载目录运行安装包，并把“进程已创建”当作安装器
已经成功调起，因此既没有规避路径兼容问题，也没有识别后续子进程崩溃。

## 被推翻的假设

- 安装包没有下载完整：哈希、大小和签名均通过。
- AI Hub 没有执行安装包：Windows 崩溃事件证明安装器已经执行。
- 官方源返回了伪造文件：签名身份与本地白名单一致。

## 通用修复

- 所有已审核桌面安装包在非 ASCII 路径下，统一复制到固定兼容启动目录。
- 兼容副本必须再次通过完整 SHA-256 和厂商签名校验，后台不能指定副本路径、
  命令或参数。
- 启动宽限期内查询与本次路径和时间严格匹配的 Windows 崩溃事件。
- 发现崩溃立即清除“安装中”任务并显示可重试状态，不再持续假报安装中。
- ASCII 路径仍直接使用原始文件，不产生无意义副本。

## 验证

- 真实安装包完成原路径失败、兼容路径成功的 A/B 检测。
- 单元测试覆盖兼容路径复制、哈希复验、签名复验和 ASCII 原路径直用。
- 启动器测试覆盖“引导进程正常退出但 Windows 报告子进程崩溃”的形态。
- Windows 崩溃事件解析按完整路径和启动时间过滤，拒绝其他程序和旧事件。

## 尚需用户验收

安装新版 AI Hub 后，从原下载路径再次点击 Comfy 的“立即安装”，确认客户端
自动使用兼容副本并显示厂商安装窗口。

## 防复发门禁

以后所有已审核 GUI 安装包都必须经过同一兼容启动模块；不得在产品页面或产品
ID 分支中单独拼接启动命令。
