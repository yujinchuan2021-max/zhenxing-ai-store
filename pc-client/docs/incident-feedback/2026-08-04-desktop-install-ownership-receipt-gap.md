# 桌面安装识别没有证明枕星 AI 所有权

日期：2026-08-04

## 现象与证据

在准备放行 Msty Go 与 Letta 时发现，现有通用桌面检测会扫描 Windows 卸载项，并按产品名称、发布者、主程序、卸载程序和数字签名识别可信安装。该结果能证明“这是目标厂商的软件”，却不能证明“该实例由枕星 AI 这次安装”。如果直接补白名单审批，用户原先手动安装的同一产品也会成为当前唯一可信候选，客户端后续卸载扫描还可能重新选择同名实例。

## 根因

桌面安装操作只持久化监测任务，没有在安装器启动前保存卸载注册表基线，也没有在安装完成时把唯一新增注册表键和规范路径写成所有权收据。产品身份与安装实例所有权被错误地当成了同一个概念。

## 排除的错误处理

- 不能为 Msty Go 或 Letta 单独硬编码默认安装目录或卸载注册表子键；不同构建器、用户选择和版本会漂移。
- 不能把“当前只有一个同名可信卸载项”当成枕星 AI 收据；它可能早已由用户手动安装。
- 不能只记录安装包 SHA-256；安装包身份不能绑定安装后实例。
- 不能在收据失效后重新扫描并自动改绑到另一个同名产品。

## 修复

- 新增通用 `post-install-registry-receipt` 所有权策略。
- 安装器启动前保存完整卸载键基线，并绑定产品、adapter、执行契约、operation ID 和截止时间。
- 安装后只接管唯一新增键；修改旧键、多个候选、扫描不完整或超时都失败关闭。
- 收据绑定精确注册表键、安装根、主程序、卸载动作及执行契约；主程序和卸载器分别重新验签。
- 后续自动管理只使用收据绑定实例。无收据的手动安装仍可按用户要求打开审核过的厂商卸载界面，但不显示为枕星 AI 自动管理。
- 只有确认精确卸载键和收据绑定的主程序都已消失后才删除收据；卸载器先删注册表、后删文件时继续保持检测中，不能提前宣布成功。

## 自动验证

回归覆盖旧手动安装不接管、唯一新增键绑定、旧键修改拒绝、多个候选拒绝、路径越界拒绝、双签名校验、收据篡改拒绝、写入失败不完成、卸载精确绑定、注册表先删除但主程序仍存在时不完成，以及过期 pending 不绑定。

## 剩余人工验收

自动化不会证明第三方安装器的真实 UI、首次启动、账户登录、更新和卸载体验。Msty Go 与 Letta 进入代码白名单后仍需在真实 Windows 用户账户单独验收；在此之前只可表述为“执行契约已审核”。

## 防复发门禁

以后凡是通过 Windows 注册表识别并由客户端自动管理的图形产品，都必须分别回答两个问题：产品身份是否可信、该安装实例是否有枕星 AI 所有权收据。两者缺一不可；新增厂商只能选择固定模块和参数，不能绕过基线与收据绑定。
