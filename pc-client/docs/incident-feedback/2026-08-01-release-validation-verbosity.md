# 发布验证日志过量

日期：2026-08-01

## 用户可见问题

本地发布每次输出数百条单测明细和完整 Docker 构建日志，重复占用对话上下文；小改动后反复运行完整发布也浪费时间。

## 根因

- 发布门禁直接使用 Node 默认测试报告器，636 个用例逐条输出。
- Docker 候选镜像使用默认进度输出。
- 日常改动和最终发布没有区分验证粒度。

## 修复

- 日常开发只运行受影响的测试；失败修复期间不重复执行完整发布。
- 最终生成验收包前仍由 `release:local:upgrade` 自动运行一次完整门禁。
- 完整门禁改用 Node 内置 dot 报告器，Docker 构建改为 quiet；失败仍返回非零并保留错误输出。

## 验证边界

精简的是成功日志，不是安全检查。正式发布仍必须完成全量测试、构建、依赖审计、桌面源审计、镜像来源校验和客户端验收；自动化仍不代替真实 Windows 安装、打开、更新与卸载验收。
