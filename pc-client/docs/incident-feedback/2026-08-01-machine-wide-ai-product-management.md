# 全机 AI 产品被误判为不可管理

日期：2026-08-01

## 用户可见问题

OpenClaw 已安装在用户选择的 AI Hub CLI 目录，产品页却显示“此安装不是由 AI Hub 部署，客户端不会接管或卸载”。这把“最初由谁安装”错误地当成了“AI Hub 能否管理”的条件。

## 证据

- `D:\AI Hub\node_modules\openclaw\package.json` 的包名为 `openclaw`，版本为客户端白名单固定的 `2026.7.1-2`。
- `D:\AI Hub\openclaw.cmd` 存在，且安装目录就是当前设置的 `cliInstallDirectory`。
- 客户端 `cli-install-records.json` 为 `{}`，因此旧状态模型只返回 `ownership: external`。

## 根因

旧模型把管理能力完全绑定到 AI Hub 安装时写入的所有权收据。收据缺失、客户端数据迁移或用户在受管目录手工安装固定官方包时，即使产品身份、版本和位置都能由本地白名单可靠确认，仍会被拒绝打开和卸载。

## 修复

- 把“来源”与“管理能力”分开：固定包名、固定版本和规范路径全部匹配时，状态为 `adopted`，仍属于 AI Hub 可管理产品。
- npm CLI 同时扫描用户选择的 AI Hub 目录和 PATH 中的精确 Windows 命令 shim，并从 shim 反推 npm prefix。
- 能写入安全收据时自动补齐收据；无法写入时仍以只读身份事实生成固定 npm 卸载动作，确认前后都重新校验包名、版本、prefix 和 manifest 摘要。
- 便携二进制、私有 Python 环境和固定 MSI 在各自审核模块内恢复收据：分别重新核对固定哈希、完整依赖锁与版本、Authenticode 与版本。
- 产品卡和“已安装的产品”页消费统一状态，不再向用户展示“AI Hub 不接管”的错误文案。

## 安全边界

- 只识别客户端本地白名单已有的厂商、产品、包名、命令、版本和安装形态。
- 同名、版本漂移、路径跳转、UNC、哈希/签名不符或身份不完整时保持不可执行状态。
- 后台仍不能下发扫描命令、包名、卸载命令或任意路径。
- 实际卸载仍需用户确认，并在确认后重新生成和比对同一个固定动作。

## 回归门槛

- 精确白名单 npm 包在无收据时必须显示为已接管，并提供打开、文件管理和卸载。
- 无固定版本的普通 npm 包仍不能自动接管。
- PATH 只接受与白名单命令完全同名的 `.cmd` shim，拒绝根目录、UNC 和近似名称。
- OpenClaw 真实安装必须在客户端刷新后显示卸载按钮，不再出现“不接管”提示。

## 剩余验收

自动化测试不代替真实机器操作。用户仍需在 PC 客户端确认 OpenClaw 的打开、文件管理和卸载按钮可见；真正点击卸载会清理 Gateway 服务，因此不在自动验收中执行。

## 全机扫描误识别补充

首次真实界面验收同时发现腾讯 `ima` 被错误映射到 `Microsoft.WebpImageExtension`。根因是旧桌面扫描对短名称使用子串匹配，`ima` 会命中 `Image`；没有 Appx 白名单的 NSIS 产品也错误参与了通用 Appx 包匹配。

修复后，桌面名称只接受客户端审核列表中的完整名称；Appx 安装证据只允许显式声明精确 identity 与 publisher 的产品使用。回归用例固定拒绝 `ima` 与 `Microsoft.WebpImageExtension` 及其 PackageFullName 的匹配。

## ima 已安装但未识别补充

真实机器上的 ima 注册信息并不使用早期假设的腾讯展示名，而是：`DisplayName=ima`、`Publisher=The ima.copilot Authors`、卸载器为 `ImaUninstall.exe --uninstall --verbose-logging`。旧 NSIS 适配器因此把真实安装判成未安装。

修复没有在页面中单独判断 ima，而是扩展统一桌面卸载适配器，使每个白名单产品可以声明准确的发布者、卸载器文件名、固定参数和交互启动方式。ima 只接受上述真实身份以及腾讯数字签名，其他近似名称继续拒绝。

## OpenClaw Node 兼容范围补充

本机 PATH 首个 Node.js 为 `25.2.1`，但 OpenClaw 当前要求 `22.22.3 <= 版本 < 23`、`24.15.0 <= 版本 < 25` 或 `25.9.0 <= 版本 < 26`；机器上另有签名有效的 `24.18.0`。旧逻辑只取第一个 Node，导致 Gateway 清理命令在不兼容运行时启动后失败。

修复后，npm 执行模块枚举所有 PATH 候选，逐个验证 Node、npm、文件树和数字签名，再按产品白名单的版本区间选择兼容运行时。安装、打开前验证和卸载前服务清理均使用同一选择器，不再把“PATH 第一项”当成唯一运行时。

## OpenClaw Windows 与 WSL 形态补充

- OpenClaw Windows Hub 已从教程条目改为已审核桌面产品，使用固定发布版本、SHA-256 和 OpenClaw Foundation 数字签名。
- WSL 仍是环境，不作为桌面产品冒充 OpenClaw。
- 新增通用 `wsl-managed` 产品驱动。产品只在客户端本地白名单声明发行版、固定安装脚本、哈希、版本、启动参数和卸载范围；后台只能引用档案，不能下发 Shell、PowerShell、CMD 或任意脚本。
- OpenClaw WSL Gateway 是首个调用该驱动的产品。驱动可由后续审核通过的 WSL 产品复用，卸载不会执行 `wsl --unregister`，也不会删除 WSL 发行版或用户配置。

## 目录发布覆盖竞态补充

生成 148 个产品的新目录后，仍在运行的后台会在任意读请求中执行 `ensureDraft()`，再把版本化存储中的 147 产品旧草稿同步回工作区 `catalog-v1.json`。浏览器轮询即可触发覆盖，造成“脚本刚生成、发布时又消失”。

修复后，后台读取草稿不再写工作区文件；只有明确的后台保存/迁移操作才更新镜像文件。本次发布先停止旧后台写入端，再生成并发布，最终后台草稿修订为 27、活动目录版本为 27，校验结果为 49 个厂商、148 个产品。

## WSL 缺少卸载与内部环境目录

已安装产品页原先只把 WSL 当成一个 Windows 可执行文件。它没有进入普通软件卸载白名单，所以卡片没有卸载按钮；扫描结果也没有发行版层级，OpenClaw WSL 安装器带入的 Node、npm、Git 对用户完全不可见。

修复后，WSL 使用独立的平台管理策略：卸载动作固定为本机签名 `wsl.exe --uninstall`，执行前列出当前发行版并再次确认，代码永远不会把 `wsl --unregister` 当成平台卸载。已安装产品页在 WSL 卡片下新增可展开子目录，按“发行版 → 内部环境”展示 Node、npm、Git 等依赖。依赖来自客户端本地审核过的产品配置，后台不能下发命令；缺失依赖通过所属产品的统一部署模块修复。

回归门槛：WSL 已安装时必须显示卸载按钮；平台卸载动作不得包含 `--unregister`；WSL 产品必须声明内部依赖；未知依赖名和任意 Shell 内容不能生成探测或安装动作。自动化验收不会实际卸载 WSL、注销发行版或改动真实 Linux 数据。

## OpenClaw 产品结构误判与安装超时补充

进一步核查官方 Windows Hub 源码和本机配置日志后，前述“把 OpenClaw WSL Gateway 放进普通 `Ubuntu-24.04` 的通用 `wsl-managed` 驱动”结论已废止。Windows Hub 会以 Ubuntu 24.04 为底层创建隔离的专属发行版 `OpenClawGateway`，再安装 Gateway、启动服务并完成配对；普通 Ubuntu 中存在 OpenClaw CLI 不能证明 Hub 的本地网关已部署。

修复后：

- Windows Hub、专属 WSL 发行版、Gateway CLI、服务就绪和 Hub 配对分别检测，不再共用一个 `installed`。
- “配置本地网关”只打开签名有效的 Windows Hub 固定 `openclaw://setup` 入口，由官方 SetupEngine 执行完整流水线。
- AI Hub 不再向普通 Ubuntu 注入 OpenClaw、Node 或 npm，也不再用十分钟桌面安装计时器覆盖官方最长约二十分钟的分阶段流程。
- 网关卸载只调用已安装 Hub 随附且哈希固定审核的 `Uninstall-LocalGateway.ps1`；该脚本只处理 `OpenClawGateway` 和对应配对状态，不删除普通 Ubuntu。
- OpenClaw Companion 的真实注册发布者 `Scott Hanselman` 已纳入精确身份规则；主程序仍必须通过 OpenClaw Foundation 签名校验。官方 Inno 卸载器本身未签名，因此仅在其 SHA-256 与当前客户端审核值完全一致时开放桌面卸载。

本机日志显示此前流程在 `wsl-create` 阶段约二十秒后收到 `pipeline_cancelled`，不是网络或 AI Hub 总超时。新的状态模型会显示“配置已取消”，不会继续等待并误报超时。

## ima 旧包与关闭安装器后假超时补充

ima 官网当前通过腾讯远程配置选择正式发行版，网页 bundle 中的 2.3.0 仅为配置读取失败时的回退包。客户端白名单已更新到 2.6.3 build 4813，并固定腾讯官方 URL、224,073,264 字节产物、SHA-256 `14102bc92f815463905c9a7fe65137f1a2d4297fb733c827db011cd6dcc3d45f` 和 Tencent Technology (Shenzhen) Company Limited 有效签名。

本机 `ima_install.log` 证明此前用户在安装界面载入后关闭了外层安装器，日志记录 `setup_ui_click_close`；AI Hub 却丢失进程退出事件，继续轮询十分钟。ima 适配器现声明为前台安装器：进程退出时立即做一次真实注册表和主程序检测；有安装证据则完成，没有证据且正常退出则标记“安装已取消”，异常退出则标记“安装失败”。安装包缓存保留，可直接再次安装。

## 产品接入资料卡门槛

所有可在本机执行安装、打开或卸载的产品现在必须先生成客户端审核资料卡，包含产品架构、组件、官方来源、安装完成证据及支持的操作。目录发布校验会同时要求本地执行白名单和资料卡；任何一项缺失时，后台数据不能把产品升级为一键安装。复合产品还必须声明组件关系，例如 OpenClaw 的 Windows Hub、专属 WSL、Gateway 服务和配对，不能把某个命令成功自行推断为整套产品完成。

## 本轮验收边界

自动化已覆盖专属发行版识别、普通 Ubuntu 拒绝、分层状态、固定深链、取消安装结束任务、真实安装证据优先、资料卡门槛、目录关系和卸载身份。本轮没有实际重新部署/删除 `OpenClawGateway`，也没有重新安装/卸载 ima；这些仍需用户在新版 PC 客户端中点击验收。
