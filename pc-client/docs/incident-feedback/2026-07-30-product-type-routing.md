# 产品类型错误共用安装流程

## 用户反馈

产品目录以厂商为第一层，但客户端只用“桌面端 / CLI / 其他产品”区分产品。普通桌面软件也被送入环境检测和安装流程，Web、本地模型与教程缺少独立行为；首页精选卡还使用厂商的第一个产品作为主标题。

## 原因

- `kind` 同时承担页面分组和执行权限，无法表达六类产品行为。
- 渲染层自己维护产品 ID 白名单，和主进程的下载、CLI、签名与卸载策略重复。
- 产品目录缺少产品级教程、安装、下载、签名和卸载策略字段。
- 首页和厂商卡片直接读取 `products[0]`，既有产品第一层表达，也无法安全支持空产品厂商。

## 修复

- 保留 XMind 的“桌面端 / CLI / 其他产品”展示分组，新增独立的六类 `productType`。
- Web、普通桌面和教程直接打开对应 HTTPS 页面，不触发环境扫描或特权 IPC。
- 已审核桌面、CLI 和本地模型才进入环境检测及受控安装流程。
- 新增客户端本地产品策略模块，校验产品 ID、厂商归属、类型、依赖和全部策略组合。
- 后台目录只能引用枚举策略；未知字段、命令字段、未审核下载、换厂商复用白名单 ID 都被拒绝。
- 托管安装包必须具备客户端固定的预期签发者；缺少签发者契约时拒绝校验和启动。
- 首页改为“精选 AI 厂商”，厂商目录按 A-Z 排列，不再由首个产品代表厂商。
- 当前目录冻结为已存在的 8 个厂商、14 个产品；XMind 未列出具体厂商或产品，因此本次未自行新增产品。

## 验证

- 目录完整性测试锁定 8 个厂商和 14 个产品，并检查每个产品的必填字段。
- 产品策略测试覆盖 Web、普通桌面、已审核桌面、CLI、本地模型和教程行为。
- 安全负测覆盖白名单 ID 换厂商、类型漂移、依赖漂移、未知命令字段和未审核下载。
- 生产构建通过，全部 212 项自动化测试通过。
- 本地页面回归确认：左侧只有主页和全部厂商；分类只在全部厂商页；普通桌面只有“前往官方下载”；Web 只有“打开网页”；CLI、ComfyUI Desktop 和 Ollama 才显示“检测环境”。

## 实机验收边界

本轮自动化和浏览器回归没有替用户打开第三方网站，也没有重新下载或运行 ComfyUI、Ollama 安装器。最终外链、真实环境检测、安装器启动、安装完成检测与卸载仍由用户在 PC 客户端验收。
