# PC 源码已更新但验收包仍是旧版

## 用户可见现象

关注、粉丝、私信和阅读记录已经在本地源码与 Docker 服务中完成，但交付给用户的 PC 包仍是更早生成的 `0.1.36`。用户只能打开 `5174` 浏览器预览，而普通网页没有 Electron 安全桥，因此无法登录或验收 PC 功能。

2026-08-04 同类问题再次出现在桌面安装入口：Msty Go、Stability Matrix 和 Audacity 在普通浏览器预览中点击后没有任何本地任务；当时尚未生成包含最新桥接与白名单的客户端包，浏览器页面也不具备 `window.aihubPC`。

## 证据

- 旧 `0.1.36` Portable 中 `listIdentityFollowers` 与 `listDirectConversations` 均不存在。
- 旧包内缺少新的固定客户端服务配置模块，包内主进程哈希也与当前工作区不一致。
- 同一个验收账号直接调用本地身份服务可以成功登录，排除了账号或身份服务故障。
- `0.1.38` Portable 从真实可执行文件启动后同时暴露 `startDownload`、`reconcileDesktopPackage`、`getDesktopStatus` 和 `deployCli`，并从远程签名目录 v71 找到 Msty Go、Stability Matrix、Audacity 三个对应模块；三个只读状态 IPC 均成功返回。

## 根因

客户端功能完成后只验证了源码、开发 Electron 和 Docker 服务，没有把“生成新的可区分版本客户端包”纳入本轮交付完成条件。与此同时，`5174` 被当作验收入口发给用户，但它只是渲染层预览，不能代替 Electron 客户端。

## 修复

- 本地验收版本递增到 `0.1.37`，避免与旧 `0.1.36` 制品混淆。
- 从当前 Caddy 根证书重新生成本地发布信任配置，不绕过封包门禁。
- 重新生成独立的 Setup、Portable、blockmap、BUILD 和 SHA-256 清单。
- 桌面安装能力只交给 Electron 客户端验收；`5174` 继续仅用于渲染层检查，不再把其中的安装按钮点击当作本地安装测试。
- 本地发布运行时同步到目录 v71 / 客户端 0.1.38，并重建 admin 镜像、强制替换 release-server，避免新包因 4443 未启动而回到“目录不可用”。

## 自动验证

- `0.1.37` Portable 内的 `dist`、`electron` 与 `shared` 文件和当前工作区逐文件一致。
- Portable 包内固定连接 `127.0.0.1:4180` 身份服务与 `127.0.0.1:8088` 社区。
- 从 Portable 包内完成真实登录，并成功读取个人中心、关注/粉丝列表和私信会话列表。
- Setup、Portable、blockmap 与 BUILD 文件的 SHA-256 均与清单一致。
- `0.1.38` Portable 实际启动后读取远程目录 v71（375 个厂商、615 个产品）；Msty Go、Stability Matrix 和 Audacity 均绑定到各自固定安装模块，未触发下载的只读状态探针全部通过。

## 边界与防复发

`0.1.37` 是未签名、脏工作区生成的本机验收包，不是正式发布包。以后客户端能力交付必须同时满足：版本已递增、制品已生成、包内桥接能力存在、包内实际登录通过；不能再把 `5174` 浏览器预览作为 PC 登录验收入口。

同一边界适用于所有本地安装动作：浏览器和后台只负责展示与目录维护；下载、安装、检测、打开和卸载必须从已封装 Electron 客户端验证。当前 `0.1.38` 仍是未签名的本机验收包，不代表三款第三方软件已完成用户点击、UAC、安装完成与卸载的实机验收。
