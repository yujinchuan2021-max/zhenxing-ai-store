# WSL 受管前缀所有权与路径替换

## 现象

Auggie 的首版 WSL 部署会直接复用已有的 `$HOME/.aihub-auggie`，并在卸载时从该路径运行 npm。若用户目录中已存在同名内容，或安装后子路径被替换为符号链接，客户端可能覆盖非受管文件，卸载动作也可能离开原本的管理边界。

同时，准备 WSL 依赖会以 root 安装 apt 软件包；这属于共享环境变更，不应伪装成只写产品私有目录的动作。

## 根因

- Windows 收据只记录产品和前缀，没有与 WSL 内的实例标记绑定。
- 安装流程不是“新目录暂存后原子提交”，对半成品和外部同名目录缺少拒绝规则。
- 探测、打开和卸载只检查命令存在，没有重新验证 realpath、符号链接和实例所有权。
- 共享 apt 环境准备没有单独告知用户其保留策略。

## 修复

- Electron 在每次安装前生成随机 48 位管理 ID；内置脚本只接受固定 `--management-id` 参数，并把同一 ID 写入 WSL 实例标记和 Windows 收据。
- 目标前缀必须完全不存在。安装在同一 WSL HOME 下的临时目录完成固定下载、哈希检查和版本探针，再以 no-clobber 方式原子移动到目标前缀。
- 探测、打开和卸载每次都校验前缀、实例标记和命令不是符号链接，realpath 精确位于固定前缀，且标记与收据一致。
- 卸载只删除该次原子创建并由收据完整拥有的专属前缀，不注销 WSL 发行版。
- root apt 前列出固定依赖并明确要求确认；这些包作为共享 WSL 环境保留，卸载单个产品时不删除。

## 预防门

所有后续 `wsl-managed` 产品必须复用同一管理 ID、原子目录和 guard 合同。后台只能选择客户端固定 profile，不能传入脚本、路径、命令、包名或参数。测试必须覆盖已有前缀、符号链接、收据/标记不一致、路径替换、取消共享环境确认和“绝不注销发行版”。
