# 统一产品安装入口

## 用户反馈

ComfyUI 已经具备下载和调起安装器能力，但 Codex CLI、Claude Code 等产品仍需要先点击单独的环境检测按钮，安装体验和产品规则不一致，后续补充厂商也容易继续分叉。

## 根因

- CLI 计划、桌面下载白名单和界面操作分别维护。
- 页面向产品行传递检测、下载、安装、CLI 部署等多组回调。
- 产品是否能托管安装没有一个统一的本地注册入口。

## 修复

- 新增统一的客户端本地安装注册表。
- 产品策略从注册表派生托管 CLI 和托管安装器能力。
- 所有产品使用同一个主操作；托管产品点击后自动检测并继续安装。
- 托管桌面产品下载并校验完成后自动打开安装器。
- 后台目录仍不能下发任意命令，也不能绕过客户端本地白名单。

## 自动验证

- 目录策略测试覆盖注册表身份、厂商、产品类型和依赖一致性。
- CLI 计划测试覆盖 Codex CLI、Claude Code 和 Gemini CLI。
- TypeScript、生产构建和全量测试必须通过。

## 仍需真实设备验收

- 在 PC 客户端内分别点击一个已安装 CLI、一个未安装 CLI 和一个托管桌面产品。
- 确认桌面产品下载结束后能调起 Windows 安装器。
- 确认缺少依赖时只停留在批准的环境安装步骤，不执行产品安装。
