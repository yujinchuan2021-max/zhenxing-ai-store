# 桌面产品安全卸载与结果确认

## 问题

客户端已经能够下载、验签并打开 ComfyUI Desktop 与 Ollama 的官方安装器，但安装完成后只能打开软件或安装位置。若直接执行 Windows 注册表中的 `UninstallString`，可写注册表项、Shell 命令、伪造发布者或相似产品名都可能把“卸载”变成任意程序执行；同时，打开卸载器也不能等同于卸载成功。

## 实现

- 第一批只开放已完成安装器审查的 ComfyUI Desktop 与 Ollama；其他桌面产品不显示卸载按钮。
- 注册表扫描必须完整成功，并且候选记录必须同时匹配固定产品名、版本后缀格式、预期发布者、安装位置和对应安装器族的卸载器文件名。
- Comfy 仅接受 electron-builder NSIS 的 `Uninstall ComfyUI.exe` 等精确兼容名，以及 `/currentuser`、`/allusers` 两个作用域参数。
- Ollama 仅接受 Inno Setup 的 `uninsNNN.exe`；注册项中的 `/SILENT` 会被识别但不会传给卸载器，确保用户看到交互式卸载向导。
- Comfy 与 Ollama 均拒绝 MSI、PowerShell、`cmd.exe`、额外开关、相对路径、UNC 路径和安装目录之外的可执行文件。
- 多个不同的可信候选不会自动猜测；只有唯一卸载动作才可继续。
- 状态页显示卸载按钮前会验证卸载器 Authenticode；用户确认前和确认后各强制验签一次，签发者 CN 必须匹配固定厂商证书。
- 二次确认框展示产品、版本、发布者、安装位置、卸载器和签发者。
- 执行使用 `spawn(executable, args, { shell: false })`，不把注册表字符串交给 Shell。
- 受管产品的“打开软件”也改为唯一可信注册项、固定主程序文件名与 Authenticode 三重验证，不再回退执行宽松名称匹配得到的 `DisplayIcon`；Ollama 的 `DisplayIcon` 指向卸载器，因此会明确寻找 `ollama app.exe`。

## 结果状态

- 打开卸载器后进入“正在确认产品是否已移除”，不能提前显示成功。
- 桌面检测改为 `installed / absent / unknown` 三态；只有注册表和 Windows 应用扫描均成功且证据确实消失时，才判定卸载完成。
- 临时注册表或 PowerShell 扫描失败属于 `unknown`，继续轮询，不会误报卸载完成。
- 每 5 秒检测一次，最多 120 次；超时后保留“立即检测”，仍不宣称成功。
- 安装和卸载共用每产品唯一的监控控制器，新流程会取消旧流程，过期结果不能覆盖当前界面。
- 确认卸载后重新读取经过主进程校验的下载记录；安装包仍存在则回到“点击安装”，否则回到“下载安装包”。

## Demo 回归修正

- Vite 开发模式显式预打包三个本地 CommonJS 运行时模块，修复浏览器 Demo 白屏。
- CSP 继续禁止内联脚本、对象和 iframe，同时允许 Vite 开发样式及产品进度条所需的内联样式，修复 Demo 裸 HTML。

## 验证边界

- 自动化测试覆盖命令白名单、路径 containment、发布者、版本后缀、NSIS 作用域、Ollama 交互化、MSI 拒绝、候选歧义、扫描未知、超时和取消。
- TypeScript、Vite 生产构建和 Node 语法检查通过。
- Playwright 浏览器回归覆盖“已安装 → 卸载中 → 确认消失 → 恢复已有安装包”的界面状态，并确认布局正常。
- 本轮没有擅自安装或卸载用户机器上的 Comfy/Ollama。真实注册表字段、安装后生成的卸载器签名和厂商卸载向导仍需用户用新客户端完成一次实机验收。
