# 已审核桌面产品分发策略漂移

日期：2026-07-31

## 用户可见问题

已审核桌面产品共用下载、验签、打开安装器和安装后复检模块，但产品策略中的发行入口与当前厂商分发方式出现漂移：

- Claude Desktop 普通用户被配置到 Team/Enterprise 使用的 MSIX。
- ChatGPT 下载文件名没有准确表达它只是 Microsoft Store 官方安装引导器。
- 目录仍使用旧名称“ComfyUI Desktop”，而当前产品名称是“Comfy Desktop”。

## 根因

统一安装模块正确限制了产品 ID、来源域名和签发者，但缺少针对“消费者版或企业版”“完整安装器或商店引导器”“产品更名”的定期一手资料复核门槛。模块复用不能替代每个产品自己的发行身份审核。

## 修复

- Claude Desktop 固定为官网普通用户 x64 EXE `latest/redirect`，企业 MSIX 不进入消费者目录。
- ChatGPT 继续使用当前 Store Product ID `9PLM9XGG6VKS`，文件名和文案明确为 Microsoft Store 官方安装引导器。
- 产品目录更新为“Comfy Desktop”，保留旧名称作为兼容探针，不自行删除 ComfyUI 实例、共享模型、输出或设置。
- Ollama 继续使用官方 `OllamaSetup.exe`；卸载只调用可信注册项，模型清理由厂商卸载器与用户共同决定。
- 新增策略回归，拒绝把 Claude 企业 MSIX 重新写回消费者目录，并锁定官方下载域名。

## 自动验证

- 目录安全策略和本地白名单单元测试。
- TypeScript 与 Vite 正式构建。
- 后台目录校验、签名发布和本地 HTTPS 升级回归。
- Windows Portable 与 NSIS 构建、安装和卸载隔离回归。

## 仍需真实用户验收

自动化不会下载或执行上述四个第三方安装器。仍需在日常 Windows 账户中逐项记录版本、SHA-256、实际 Authenticode 发布者、安装后探针、更新行为和卸载后的数据保留结果。

## 防回归门

发行入口变更必须同时更新本地白名单、后台目录、回退目录、研究记录、用户验收清单和策略测试；任何后台 URL 都不能绕过客户端固定来源与签发者校验。
