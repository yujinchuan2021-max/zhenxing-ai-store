# 目录体积与生态资源契约漂移

- 日期：2026-08-03
- 影响：后台目录保存、连接器商店、中英文界面和生态资源安全说明

## 现象

- 厂商目录持续扩充后，当前保存请求已接近 0.5 MiB；后台所有 JSON 接口仍共用 1 MiB 上限，继续扩充会在数据合法时突然保存失败。
- 正式目录已经包含 `connector` 商店，但共享资源类型、默认商店、后台回退和客户端语言映射并未全部同步，可能造成某个环境能显示、另一个环境隐藏或英文界面继续显示中文。
- Unity 官方 MCP 与向日葵 AweSun MCP 的当前目录记录缺少版本、权限、凭据、安装范围和卸载计划；来源脚本也没有固定这些字段，后续重跑会继续丢失。

## 根因

1. 通用请求读取器把目录保存和普通小型接口视为同一种负载，没有给唯一的大对象路由设置独立边界。
2. 新资源类型分别写入目录、后台和客户端，缺少一份跨层契约测试。
3. 资源补录只关注名称、链接和目标产品，没有把五项安全说明纳入来源脚本与正式草稿的双重门禁。

## 修复

- 提取统一 JSON 读取器：普通接口继续限制 1 MiB，仅 `PUT /api/catalog` 显式允许 4 MiB。
- `connector` 同步进入共享资源类型、默认商店、后台回退、中文和英文语言模块，并由客户端固定标签映射显示。
- Unity 与向日葵两项资源同时补齐 `versionRef`、`requestedPermissions`、`credentialRequirements`、`installScope` 和 `uninstallPlan`；来源脚本和当前草稿都受测试约束。
- 资源商店继续使用“商店 → 目标工具 → 资源列表 → 单项详情”，厂商和产品身份合并显示在工具卡，不额外增加无内容的点击层。
- 重建本地后台后通过统一脚本发布目录 v48；`/ready` 返回草稿 51、活动目录 48，浏览器验证连接器商店三层钻取与单项详情均可用。

## 防复发

- 请求边界测试同时覆盖 1 MiB、4 MiB、恰好等于上限和超过 1 字节；只有目录保存路由可以引用 4 MiB 常量。
- 每增加一种资源商店，测试必须同时看到共享类型、默认商店、后台回退、双语键和客户端标签映射。
- 来源脚本与正式目录中的高权限资源必须同时包含五项安全字段；只修改生成脚本或只修改当前 JSON 都不能通过。
- 目录变化后继续运行全量发布测试、生产构建、后台校验和统一签名发布，不把磁盘 JSON 更新当作客户端已经收到新版本。
- 内容寻址 Logo 的清理范围必须同时扫描当前草稿和全部历史签名目录；历史引用仍存在的文件不是垃圾，不能在新目录发布前或发布后直接删除。
