# 安装程序启动后立即退出

## 用户现象

产品安装包已经下载并通过签名检查，但用户点击“点击安装”后看不到安装向导，界面像是没有响应。

## 本机证据

- AI Hub 下载记录中的 Comfy 安装包位于 `C:\Users\yujin\Desktop\Comfy-Desktop-Setup-x64.exe`。
- 文件大小为 158,888,904 字节，SHA-256 为 `41373c8430e9b3b8e8e1fdd66feb7fc4299a03a6ac1bf9cdb654391ad932e443`，与客户端完成记录一致。
- Authenticode 状态为 `Valid`，签发者为 `Drip Artificial Inc`。
- Windows Application Error 事件记录了两次安装器崩溃：故障模块 `System.dll`，异常代码 `0xc0000005`。
- 同一个已验证文件随后再次启动成功并显示“Comfy Desktop 安装”窗口，因此不能把该问题归类为下载损坏。

## 原因

主进程原来使用 `shell.openPath()`，只能确认 Windows 接受了打开请求，无法发现安装程序随后立即崩溃。与此同时，前端在两次 SHA-256 检查和确认对话框期间没有进入不可重复点击状态，主进程也没有产品级启动互斥。

## 修复

- 已验证的 `.exe` 使用无 shell 参数的受控子进程启动，并观察两秒启动窗口。
- 子进程在启动窗口内以非零代码退出时，返回“安装程序启动后立即退出”和 Windows 十六进制退出码。
- 正常保持运行超过启动窗口，或引导程序以代码 0 交接给子进程时，才进入安装结果监控。
- 主进程按产品阻止并发启动，前端点击后立即显示“正在验证并启动安装程序…”，避免重复点击。
- 启动失败不会丢弃可信下载记录，也不会要求重新下载；产品卡片显示明确错误和“重新打开安装包”。

## 验证

- 真实子进程回归覆盖立即失败、持续运行和成功交接三种结果。
- Playwright 覆盖启动中、`0xc0000005` 可见错误、保留下载包和重试成功。
- 界面截图：`output/playwright/installer-launch-failed-retry-1180.png`。

## 验收边界

自动化确认的是“安装程序是否成功启动并保持运行”，不等于厂商软件已经安装完成。最终安装结果继续由 Windows 应用证据扫描和用户完成厂商安装向导共同确认。
