# Claude 卸载能力与模块契约漂移

## 现象

Claude Desktop 已经安装，但产品卡片不显示可用的卸载功能。

## 证据

- Windows 卸载注册表包含 `AnthropicClaude`。
- 安装位置为用户目录下的 `AnthropicClaude`。
- 卸载入口为签名有效的 `Update.exe --uninstall`。
- 客户端原有 Claude 探针只声明了 Appx/MSIX 身份，没有声明当前 EXE
  发行版的卸载适配器。

## 根因

后台产品模块声明 `client-managed` 卸载策略，客户端执行层却维护了另一份
独立的产品探针。Claude 下载策略从 MSIX 切换为 EXE 后，第二份配置没有同步，
导致声明能力和可执行能力漂移。

## 被推翻的假设

仅凭产品类型或 `uninstallPolicy` 就可以推断客户端一定拥有对应卸载实现。

## 修复

- 产品模块公开统一的 `capabilities` 能力清单。
- 安装档案声明本地已经审核的能力和桌面适配器。
- 后台只能启停已审核能力，不能增加命令、参数或可执行文件。
- 客户端按照能力清单通用渲染官网、教程、安装、打开和卸载。
- Claude 绑定经过审核的 Squirrel EXE 适配器，同时保留旧 Appx 检测兼容。
- 卸载时优先匹配当前机器的可信注册表安装；没有可信 EXE 安装时才尝试 Appx。

## 验证

- 单元测试覆盖 Claude 的 `Update.exe --uninstall` 注册表形态。
- 契约测试保证每个托管桌面产品声明的卸载能力都有本地适配器。
- 发布校验拒绝后台请求模块或安装档案未批准的能力。
- TypeScript 构建和完整测试套件通过后才允许发布。

## 尚需用户验收

在真实 Claude 安装上点击卸载，确认弹出 AI Hub 的安全确认框，并在确认后打开
Claude 厂商卸载流程；取消确认不得启动卸载器。

## 防复发门禁

以后切换桌面发行格式时，必须同时满足下载策略、检测适配器、打开适配器和卸载
适配器的一致性测试。后台可以删除或恢复现有能力，但新增本地执行能力必须随
客户端白名单更新发布。
