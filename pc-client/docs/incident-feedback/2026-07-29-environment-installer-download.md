# 环境安装按钮只打开网页

## 现象

产品缺少 Python、Node.js、Git 或 Docker 环境时，“安装环境”按钮只打开官网页面，用户还需要自己寻找 Windows 安装包。

## 根因

`environment:install` 只保存了环境官网 URL，并调用 `shell.openExternal`。客户端没有环境安装包白名单、区域源选择、下载记录，也没有“下载完成后由用户主动打开”的状态。

## 修复

- 客户端固定维护环境版本、文件名、官方源与可信镜像，不接受 CMS 下发任意安装地址。
- 点击安装后始终先探测官方下载地址，不再依据 Windows 区域或语言改变顺序。
- 官方源要求 HTTPS、允许的最终主机名以及 `200/206` 响应；官方源不可用时才探测可信镜像。
- 官方源通过探测后直接下载；若下载失败或连续 12 秒没有任何数据，则清理临时文件并尝试可信镜像。
- 若 `HTTPS_PROXY`、`ALL_PROXY` 或 `HTTP_PROXY` 指向 `127.0.0.1`、`localhost` 或 `::1`，Electron 会使用该本地代理；远程地址或带账号密码的代理环境变量会被拒绝。
- 探测与下载使用同一 Electron `net.fetch` 通道和固定 Windows 客户端 User-Agent，避免出现探测可用但下载通道行为不同。
- 下载完成后验证 Authenticode 发布者并记录 SHA-256。
- 下载和运行分成两个动作：第一次点击只下载，按钮随后变为“打开安装包”；仅第二次点击才调用 Windows 打开安装包。
- 再次打开前复验文件存在性、SHA-256、数字签名和发布者。

## 已排除的方案

- 仅依赖 `winget`：当前测试机没有 `winget`，不能作为基础能力。
- 自动运行下载完成的安装包：用户没有进行第二次明确确认。
- 根据不可信远端配置执行下载：会扩大 CMS 对本机执行面的控制。
- 使用未验证的镜像路径：Git 的候选镜像实测返回 `404`，因此没有加入白名单。

## 验证

- 单元测试覆盖国内/海外源排序、镜像失败回退、全部源失败和未知环境拒绝。
- 清华 Python 镜像真实下载 `python-3.13.14-amd64.exe` 成功。
- Windows Authenticode 状态为 `Valid`，签发者为 Python Software Foundation。
- SHA-256：`C54D9B9BBB8A36E6489363DDD01139707FD781D72F1F9E90C7EC65D0061368E0`。
- Clash Verge/Mihomo 本机验收中，系统命令通过 `127.0.0.1:7897`，而 Electron 初始解析为 `DIRECT`；接入可信本地代理后，真实 UI 流程完成官方下载与验签，并显示“打开安装包”。
- PowerShell 验签路径改由受控环境变量传入，避免 `-Command` 后的文件路径被误解析而令 `$args[0]` 为空。

## 尚需人工验收

- 点击“安装 Python”，确认立即显示“正在检测官方下载源…”，随后显示下载百分比，再变为“打开安装包”。
- 点击“打开安装包”，确认 Windows 安装向导启动；下载完成时不得自动启动。
- 人为屏蔽官方源时，确认客户端才会尝试可信镜像。

## 防回归门槛

环境安装功能必须同时满足：官方优先、镜像兜底、固定来源白名单、下载前探测、下载停滞回退、HTTPS 最终主机校验、下载后数字签名校验、用户二次点击才运行。
