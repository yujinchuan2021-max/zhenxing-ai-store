# CLI 与生态资源生命周期闭环

日期：2026-08-03

## 现象

- CLI 更新或修复失败后点“重试”，旧任务只记录为“部署”，会退化成普通安装。
- 后台关闭某个资源能力时，客户端把远端能力集合与本地集合做完全相等比较，导致其他已保留能力也全部失效。
- 后台停用或删除资源后，商店入口消失，已安装资源也失去卸载入口。
- 宿主 CLI 未安装时，资源卡显示“未安装”却没有明确的宿主缺失状态。
- Claude Code 插件仅凭同名收据可能在用户手动卸载并立即重装同版本后误认所有权。
- MCP 配置或 CLI 包已经更新，但新收据落盘失败时，宿主状态与旧收据可能不一致。
- 源码目录已经包含新能力，但运行中的后台 Docker 镜像仍使用旧模块白名单，正式目录发布被拒绝。

## 根因

1. UI 任务模型丢失了 `install/update/repair` 原始意图。
2. 资源授权把“远端能力必须是本地固定能力的子集”错误实现成集合完全相等。
3. 已安装页依赖当前远端目录，没有独立读取客户端本地收据。
4. 管理器没有把 `not-installed + hostInstalled=false` 投影为 `host-missing`。
5. 插件收据只绑定产品身份，没有绑定 Claude 自己记录的安装实例。
6. 配置/包更新和收据提交缺少补偿事务。
7. 后台源码与容器镜像是两个状态层；只更新宿主文件不会替换镜像中的共享校验模块。

## 修复

- CLI 任务统一保存 `install/update/repair/uninstall`，重试原样调用对应动作；通知与托盘协议同步支持四种动作。
- CLI 更新与修复进入客户端固定模块和后台能力模型；授权按当前动作复核最新签名目录。
- 资源授权允许后台能力为本地白名单的子集，但拒绝后台新增能力、命令、包名、路径或配置内容。
- 新增本地资源清单 IPC；只枚举固定 profile 的本地收据，排除外部安装，并允许受管内容离线卸载。
- 宿主探测改为纯只读状态查询，未安装宿主明确显示 `host-missing`。
- Skill 使用文件清单，MCP 使用固定 TOML 表，Claude 插件同时使用管理标记和 `installed_plugins.json` 实例指纹；任何所有权不一致都拒绝变更和卸载。
- MCP 收据失败回滚原配置；CLI 更新/修复收据失败恢复原包、原管理标记和原收据。
- 重建并强制重建后台容器后重新校验、签名并发布目录；活动目录更新为 v61、草稿修订 64。

## 自动验证

- 固定适配器、授权、收据、离线清单和任务通知聚焦测试通过。
- 目录扩充脚本连续运行两次，`catalog-v1.json` SHA-256 保持不变。
- 后台校验通过：375 个厂商、615 个产品、146 个资源；签名目录 v61 发布成功。
- 生产 TypeScript/Vite 构建通过。

## 仍需人工验收

- 在用户日常 Windows 账户与真实网络下，分别验证 Codex/Claude/Gemini/OpenClaw CLI 的安装、更新、修复、命令窗口和卸载。
- 使用真实 Codex 与 Claude Code 宿主验证首批 Skill、MCP、插件的安装、启停、更新、修复和卸载。

## 防复发门禁

1. 新增生命周期动作必须同时更新固定模块、目录能力、IPC 类型、任务原意、通知和测试。
2. 已安装内容的清理入口必须来自本地收据，不能只依赖远端目录是否仍展示。
3. 所有权必须绑定具体安装实例；名称、版本或路径单独任何一项都不足以授权卸载。
4. 宿主写入和收据写入视为一个事务；后一步失败必须恢复前一步或降级为不可管理且不可卸载。
5. 目录发布前连续运行生成脚本两次并比较哈希；Docker `COPY` 涉及的共享模块变化后必须重建并强制重建对应容器。
