# 核心桌面产品生命周期缺口复盘

日期：2026-08-01

## 用户可见问题

- 已安装产品点击“重新安装”会再次检测到已安装并直接结束，按钮实际无效。
- 已安装产品调起重装或更新安装器后，又会被“当前已经安装”立即误判为本次操作成功。
- “获取最新版”创建的新下载任务从 revision 1 开始，渲染端可能按旧任务 revision 丢弃；另一产品占用全局下载槽时还可能先删掉当前可信安装包再拒绝下载。
- 外部卸载后，产品卡仍可能保留“已安装”状态。
- 后台停用或删除产品卡后，缓存安装包仍显示“立即安装”。
- ChatGPT 可退化为同名普通卸载项证据，存在误报和打开非审核程序的风险。
- Claude 与 Comfy 仍使用旧下载入口；Comfy 还会提前安装没有官方依据的系统 Python。
- 四款产品没有统一表达更新所有者、数据保留和安装器产品身份。
- 卸载确认和卸载中状态没有读取数据保留契约，用户看不到 Comfy 会保留哪些目录，也不知道 Ollama 必须在厂商卸载器中选择是否删除模型。
- 旧 ComfyUI Desktop V1 的名称、主程序和卸载项曾与当前 Comfy Desktop 共用探针，会把旧版误报成当前产品。
- Claude 曾沿用一次设备观察结果被标记为自动卸载，但厂商公开文档没有稳定静默卸载契约。

## 根因

- 安装流程只有一个 `install` 意图，没有区分首次安装、重新安装和强制获取最新版。
- 首次安装、重装和更新共用“从未安装到已安装”的结果监控；后两者启动时基线本来就已安装。
- 下载任务 revision 没有按新任务代际重置，刷新流程又在全局下载准入前执行了破坏性清理。
- 管理页将本地白名单恢复能力与后台启停权限混成一个上下文。
- 下载完成回调、任务中心恢复和安装异步链路继续持有旧渲染快照中的产品对象，没有在真正下载或启动安装器前重新确认后台启用状态。
- 桌面扫描只累加安装证据，没有处理可信 `absent` 的反向状态迁移。
- 安装器校验只覆盖路径、哈希和签发者，没有覆盖 PE 架构和 VersionInfo。
- 四款产品沿用了早期研究结论，执行契约与当前厂商文档发生漂移。

## 统一修复

- 新增 `install / reinstall / refresh` 三种统一意图；所有入口仍先做新鲜环境和产品检测。
- 安装意图一路传到主进程，但主进程不会信任渲染端声称的操作类型：运行前重新读取可信产品状态，仅可信 `absent` 创建安装状态迁移监控；重装和更新由厂商安装器负责，客户端保留原有已安装状态且不宣称新版本已经完成。
- `reinstall` 可复用可信缓存；`refresh` 将最新版下载到独立文件，完成 SHA-256、Authenticode 和安装器产品身份校验并原子提交新记录后，才精确清理旧包。下载、校验或记录提交失败时，旧可信包仍可安装。
- 旧包暂时被占用时，清理收据与新下载记录在同一次原子写入中持久化；收据严格绑定产品、根目录、文件名、大小和 SHA-256，最多 16 条，并在启动及下次刷新前重试。收据路径被篡改时不执行删除，队列满时停止继续制造新副本。
- 下载任务展示游标同时绑定 `attemptId`、attempt 和 revision；迟到旧任务即使 revision 更大也不能覆盖新代际，全局下载槽未获准时不会进入任何旧数据清理。
- 后台已停用产品只保留已安装实例的打开、文件管理和卸载，不再允许安装、重新安装或获取最新版；渲染端所有恢复入口会从最新界面快照重新解析，主进程还会在下载、刷新、启动安装器和 CLI 部署前即时读取后台远程发布目录。后台不可达而只能得到旧缓存时，新的安装操作失败保护，不能复用停用前捕获的产品对象。
- 可信 `absent` 会清除安装证据并回到 `downloaded` 或 `ready`；`unknown` 继续失败保护。
- AppX-only 产品不再使用普通同名卸载项作为安装证据。
- 普通桌面产品的注册表证据必须同时绑定受信任主程序的 Authenticode 结果；Windows 验签命令暂时不可用时状态为 `unknown` 且不缓存为“未安装”。
- 四款产品建立本地只读生命周期契约，后台不能覆盖更新、数据保留或安装器身份。
- 启动安装器前新增 PE 架构和 VersionInfo 校验，并让检查与启动共用同一门禁。
- 更新 Claude/Comfy 当前官方入口并移除 Comfy 的无依据 Python 依赖。
- 卸载确认、卸载中状态和超时提示共用本地数据保留展示模块：Comfy 列出三个保留目录；Ollama 明示模型删除由厂商卸载器决定，并要求用户在卸载器中选择和确认。
- 当前 Comfy Desktop 探针只接受当前名称、`Comfy Desktop.exe` 和当前卸载项；旧名称、旧主程序或旧卸载项只形成签名校验后的只读迁移提示，不计入当前版安装状态。
- Claude 统一为厂商交互式卸载。注册表若登记 `Update.exe --uninstall -s`，客户端先按完整命令、发布者、目录和签名白名单验证，再仅剥离 `-s` 调起厂商 UI；额外参数仍被拒绝。

## 回归门禁

- 新增核心桌面生命周期、状态回收、后台停用、主进程即时目录授权、异步下载完成与失败恢复启用态门禁、安装器身份、注册表验签绑定、下载任务代际、安全替换和跨重启清理收据测试。
- 新增卸载数据保留展示测试，覆盖 Comfy 的全部保留目录和 Ollama 的模型删除选择。
- 新增 Comfy 新旧身份隔离、迁移提示和 Claude 静默参数收窄测试。
- 完整 Node 测试必须全绿。
- TypeScript、Vite 构建、桌面下载源审计和本地发布链路必须再次通过。
- 自动化通过不代替四款产品的 Windows 实际安装、启动、更新、卸载与数据保留验收。
