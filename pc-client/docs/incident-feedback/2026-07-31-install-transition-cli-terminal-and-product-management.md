# 安装过渡、CLI 终端与已安装产品管理

## 用户症状

- 点击桌面端或 CLI 的“一键安装”后，操作按钮短暂消失，直到下载或部署界面出现。
- CLI 安装完成后只显示完成状态，没有打开可直接使用的命令窗口。
- 本机 Docker Desktop 已安装，但卸载按钮不可用。
- 缺少统一的已安装产品与本地安装包管理入口。

## 证据

- `ProductRow` 只渲染 `idle`、`blocked`、`ready`、`downloading` 等状态，没有渲染
  `detecting`，因此安装准备期间操作区为空。
- CLI 的 `deploying` 状态使用独立日志卡，没有复用安装状态展示模块。
- 本机 Docker Desktop 4.83.0 注册表项为：
  - 发布者：`Docker Inc.`
  - 安装位置：`C:\Users\yujin\AppData\Local\Programs\DockerDesktop`
  - 卸载命令：`"Docker Desktop Installer.exe" "uninstall"`
- Docker 安装器与主程序 Authenticode 均为 `Valid`，签发者为 `Docker Inc`。
- 旧命令解析器不接受带引号的单个参数，导致可信卸载动作被错误拒绝。

## 根因

产品状态展示、CLI 部署展示和环境卸载命令解析分别演进，统一产品模块没有覆盖
“准备中”状态、CLI 使用入口和 Windows 注册表常见的引号参数格式。已安装产品的
操作能力也散落在产品页与设置页，没有一个目录驱动的管理模型。

## 已排除的错误假设

- Docker 没有官方卸载器：本机注册表、文件和有效签名均证明卸载器存在。
- Docker 卸载按钮不可用是因为程序正在运行：能力判定发生在操作前，与运行状态
  无关。
- CLI 安装成功后只能显示完成提示：受管 CLI 收据已经足以安全定位固定命令入口。

## 修复

- 安装展示模块新增：
  - `detecting`：灰色禁用按钮“正在准备”；
  - `deploying`、安装器启动和结果确认：灰色禁用按钮“正在安装”。
- 产品卡不再为 CLI 部署显示另一套日志卡。
- 本地 CLI 白名单增加固定命令名；受管安装成功并写入收据后，自动打开可持续使用
  的命令窗口。管理页可再次打开该命令窗口。
- Windows 卸载命令解析器支持独立的带引号参数，同时仍拒绝额外参数、Shell 命令和
  非白名单卸载器。
- 顶部设置旁新增“已安装”入口。目录驱动的管理模型统一汇总桌面端、CLI、运行环境
  和已验证安装包，按本地能力显示打开、关闭、文件管理、重新安装和卸载。
- 安装包管理提供立即安装、打开文件夹和删除安装包。删除只作用于经过客户端重新
  校验的固定下载记录，并在用户二次确认后执行。

## 自动验证

- 回归测试先稳定复现：
  - `detecting` 和 `deploying` 返回空展示；
  - Docker 的 `"uninstall"` 参数不命中；
  - CLI 终端和已安装产品管理模块不存在。
- 修复后专项测试 23 项通过。
- TypeScript、Vite 构建通过。
- Electron 真实页面回归通过：
  - 产品操作按钮同线；
  - Docker 的打开、关闭、文件管理和卸载按钮均出现且可用；
  - Claude 安装包显示立即安装、打开文件夹和删除安装包。

## 剩余实机验收

- 用新版本实际安装一个受管 CLI，确认安装结束后命令窗口自动打开并进入对应 CLI。
- 在已安装管理页手动打开和关闭一个桌面产品。
- Docker 卸载会改变本机开发环境，自动化没有代替用户点击；需用户决定何时执行。
- 删除安装包会删除本地文件，自动化只验证入口与安全约束，没有擅自点击。

## 防复发门槛

- 每个非终态安装阶段必须在展示模块中返回可见状态，不能由产品卡自行遗漏。
- 每个受管 CLI 安装配置必须声明固定命令名，并通过收据、目录和入口三重校验。
- Windows 卸载解析必须覆盖等价的引号写法，仍以精确参数白名单为最终判定。
- 管理页只能消费目录和本地状态形成的能力模型；后台不能下发进程名、命令或删除
  路径。
