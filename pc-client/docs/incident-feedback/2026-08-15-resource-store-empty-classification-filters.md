# 资源商店展示无证据分类并产生空结果

## 用户现象

Skill 商店展示完整“场景”与“Agent 兼容性”按钮，但选择“Agent/多Agent”等条件后没有任何资源，用户无法判断是目录确实为空，还是分类数据没有完成。

## 现场证据

- 当前活动签名目录 v7 有 120 个 Skill，但 120/120 都没有 `scenarioTags`。
- 活动产品目录没有可支撑旧“兼容 Agent / 成熟 Agent”筛选的 `agentTag` 或 `agentChannel` 事实。
- 后续候选中 104 个社区 Skill 已有 canonical `scenarioTags`，18 个官方 Skill 仍未分类；这不能反向补写活动目录。
- ResourceTarget 已有真实、受校验的 `compatibility` 值，可作为当前兼容性筛选事实源。

## 根因

前端把 taxonomy 中所有可能的场景标签都当成当前目录已拥有的 facet，并把产品级 Agent 成熟度字段误用为资源兼容性。筛选按钮因此不是由当前数据派生，能稳定制造“合法但永远为空”的组合。

## 修复

- 资源 marketplace 新增只读 `facets({store, source})`，场景计数仅来自当前资源的 canonical `scenarioTags`，兼容性计数仅来自当前 ResourceTarget 的 `compatibility`。
- 前端只展示当前来源中计数大于 0 的场景；没有场景数据时明确显示“当前目录尚未提供可用的场景分类”，不伪造完整分类。
- 兼容性改为“官方兼容 / 已验证兼容 / 协议兼容”，并显示实际数量；切换来源或目录后自动清理已失效筛选值。
- 同时选择宿主与兼容性时，两项必须命中同一个 ResourceTarget，不能由资源的两个不同宿主分别满足条件。
- 不把后续候选标签写回活动签名目录，不把热度、成熟度或产品频道升级成兼容性事实。

## 验证

- TDD 首轮精确失败：marketplace 没有 facet 投影，兼容性过滤不可用。
- 修复后 marketplace/UI 聚焦测试 12/12 通过；无效兼容值、同一目标交集、来源切换和真实数量均有覆盖。
- 前端 build、lint 与 scoped diff-check 通过。

## 预防门

筛选项必须由当前已加载目录的真实 facet 生成；任何 taxonomy 常量只能校验值，不能自动变成“有数据”的按钮。活动目录缺失分类时必须诚实显示缺口，分类候选只有经过独立目录发布后才能出现在用户端。
