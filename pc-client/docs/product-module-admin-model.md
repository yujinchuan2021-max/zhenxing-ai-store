# 后台产品模块模型

## 后台调用方式

后台不直接调用本地程序，而是在目录中声明：

- `moduleId`：产品使用的通用模块。
- `installProfileId`：客户端已审核的具体安装配置。
- 产品名称、描述、图标、官网、教程、分类、顺序和启停等展示资料。
- `directoryKind`：产品唯一的目录职责，只能是 `ai-tool` 或 `ai-connectable`。
- `entryPoints`：产品卡片中的有序入口；链接入口只允许 HTTPS，本地入口只选择桌面或 CLI 类型，不携带执行参数。

PC 客户端读取目录后，在本地解析并执行对应模块。

同一可视化产品只建立一条产品记录。后台可以按需要增加“工具官网”“产品网页版”“Windows 客户端”等入口，数组顺序即按钮顺序；不存在的入口不展示。CLI 必须单独建立产品记录，并在客户端明确标注为命令行工具。

“全部 AI 厂商”和“全部 AI 可接入厂商”不是两套厂商表。客户端从启用产品的 `directoryKind` 投影厂商，并在每个页面只展示对应产品；产品不能依靠厂商级布尔值跨页面泄漏。

## 生态资源模型

catalog schema v2 不再在产品中保存 `extensions`。生态资源位于顶层 `resources`，每个资源只保存一次：

- `resourceTypes`：由 `skill`、`mcp`、`plugin` 组成的非空数组。
- `sourceProductIds`：资源所连接或带入能力的来源产品。
- `targets`：资源的接收产品关系；每项包含 `productId`、`compatibility`、`moduleId`、`installProfileId` 和 `capabilities`。

资源商店只是一组投影视图，顺序固定为“资源类型 → 目标厂商 → 目标产品”。同一资源兼容多个产品或同时属于多个类型时，页面引用同一个资源身份和版本，不复制后台记录。产品详情页不再渲染 Skill/MCP 子目录。

资源目标中的模块和安装配置与产品本地执行使用同一安全原则：后台只能选择客户端公开且已经批准的 ID，不能输入包名、URL、命令、参数、配置片段或文件路径。每个“资源 × 目标产品”组合必须独立校验并保存所有权收据。

## 当前模块

| moduleId | 用途 | 是否需要审核配置 |
| --- | --- | --- |
| `web-link` | 打开 Web 产品 | 否 |
| `desktop-official` | 打开厂商官方下载页 | 否 |
| `desktop-managed` | 桌面软件检测、下载、校验、打开安装器 | 是 |
| `cli-managed` | CLI 环境检测、部署、验证和卸载 | 是 |
| `local-model-managed` | 本地模型工具安装和检测 | 是 |
| `tutorial-link` | 打开教程 | 否 |

模块统一派生产品形态、产品类型、安装策略、下载策略、签名策略和卸载策略，后台不再分别编辑这些字段。

## 审核配置

审核配置只公开给后台以下信息：

- 配置 ID 和显示名称。
- 允许绑定的厂商 ID、产品 ID和模块 ID。
- 固定环境依赖。
- 托管桌面产品可写回客户端本地白名单中的只读下载地址和文件名。

CLI 包名、命令、发布者签名、允许跳转的下载域名和执行细节仍保留在客户端本地实现中。后台不能输入下载地址；只能使用审核配置提供的只读默认值。后台选择错误配置、跨厂商复用配置或给直达模块绑定配置时，保存或发布校验失败。

托管桌面产品另有“待审核／已审核／已实机验收”工作流。认证记录只描述当前本地执行契约的审核进度，不会创建白名单：

- 待审核产品不能发布 `install` 能力。
- 已审核表示完整执行契约与客户端本地审批哈希一致。
- 已实机验收还必须绑定同一执行契约，并记录七项真实 Windows 行为证据。
- 后台可以冻结产品或记录验收，不能输入 EXE、URL、Shell、PowerShell、CMD、安装参数或卸载参数。
- 后台停用产品后，客户端仍允许用户打开、管理和卸载已经安装的实例。

## 新厂商接入

仅展示或跳转的产品可以直接选择直达模块并修改文字资料。产品入口、按钮文字和 HTTPS 链接可以通过已签名目录更新，不需要修改前端页面。桌面与 CLI 的本地安装、检测、打开和卸载仍只能绑定客户端当前版本已有的审核配置；后台不能下发命令、参数或本地路径。只有新增本地执行原语时才需要升级客户端。
