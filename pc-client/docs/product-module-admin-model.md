# 后台产品模块模型

## 后台调用方式

后台不直接调用本地程序，而是在目录中声明：

- `moduleId`：产品使用的通用模块。
- `installProfileId`：客户端已审核的具体安装配置。
- 产品名称、描述、图标、官网、教程、分类、顺序和启停等展示资料。

PC 客户端读取目录后，在本地解析并执行对应模块。

## 当前模块

| moduleId | 用途 | 是否需要审核配置 |
| --- | --- | --- |
| `web-link` | 打开 Web 产品 | 否 |
| `desktop-official` | 打开厂商官方下载页 | 否 |
| `desktop-managed` | 桌面软件检测、下载、校验、打开安装器 | 是 |
| `cli-managed` | CLI 环境检测、部署、验证和卸载 | 是 |
| `local-model-managed` | 本地模型工具安装和检测 | 是 |
| `tutorial-link` | 打开教程 | 否 |

模块统一派生产品形态、产品类型、安装策略、下载策略、签名策略和卸载策略，后台不再分别编辑这些字段。

## 审核配置

审核配置只公开给后台以下信息：

- 配置 ID 和显示名称。
- 允许绑定的厂商 ID、产品 ID和模块 ID。
- 固定环境依赖。
- 托管桌面产品可写回客户端本地白名单中的只读下载地址和文件名。

CLI 包名、命令、发布者签名、允许跳转的下载域名和执行细节仍保留在客户端本地实现中。后台不能输入下载地址；只能使用审核配置提供的只读默认值。后台选择错误配置、跨厂商复用配置或给直达模块绑定配置时，保存或发布校验失败。

托管桌面产品另有“待审核／已审核／已实机验收”工作流。认证记录只描述当前本地执行契约的审核进度，不会创建白名单：

- 待审核产品不能发布 `install` 能力。
- 已审核表示完整执行契约与客户端本地审批哈希一致。
- 已实机验收还必须绑定同一执行契约，并记录七项真实 Windows 行为证据。
- 后台可以冻结产品或记录验收，不能输入 EXE、URL、Shell、PowerShell、CMD、安装参数或卸载参数。
- 后台停用产品后，客户端仍允许用户打开、管理和卸载已经安装的实例。

## 新厂商接入

仅展示或跳转的产品可以直接选择直达模块并修改文字资料。需要一键安装的新产品，先在客户端增加并审核安装配置、完成测试和发版，再由后台绑定该配置。
