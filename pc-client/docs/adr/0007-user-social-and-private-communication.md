# ADR-0007：用户关系与私密沟通的数据归属

状态：已采用

## 决策

统一身份服务保存用户之间的有向关注关系和一对一私信记录；会话按消息双方实时投影，粉丝按关注关系反向查询，二者都不单独保存第二份实体。系统发送的站内信继续使用现有站内信模型，不与用户私信合并。Flarum 继续保存讨论、回复、讨论关注、喜欢、社区提醒以及 `discussion_user.last_read_at` 阅读记录，身份服务只通过受限内部桥聚合社区摘要和阅读记录。PC 个人中心是这些能力的统一入口，但不会复制任何 Flarum 社区状态。

## 约束

- 当前只支持一对一文本私信，不提前实现群聊、附件、撤回、拉黑或已读回执明细；
- 当前用户只能由已认证会话推导，客户端不能指定关注者、消息发送者或阅读记录所属用户；
- 用户私信、站内信和社区提醒必须在界面与接口中保持不同名称；
- 关注、粉丝、会话和私信内容按个人中心标签分页懒加载；打开的私信页只做低频刷新，周期性全局个人中心刷新仍只读取计数摘要；
- 私信发送限额在数据库事务内按发送者加锁后判断，不能被并发请求绕过；同一对用户反复取消和重新关注只产生一次系统关注提醒；
- 社区阅读记录以 Flarum 为唯一事实源，客户端不从 `webview` 重复上报。

## 后果

身份数据库新增关注和私信记录；Flarum 内部个人中心桥新增阅读记录投影。个人中心可以统一展示关注、粉丝、私信、站内信和阅读记录，同时保持身份数据与社区数据的清晰边界。
