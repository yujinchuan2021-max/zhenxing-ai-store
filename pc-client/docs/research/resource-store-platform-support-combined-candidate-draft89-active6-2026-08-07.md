# Four resource stores platform support combined candidate

Status: **candidate only** and not publishable. This is the only recommended
combined input for the current seven research files; the individual reports
remain immutable evidence sources.

The candidate normalizes 150 store-specific evidence contributions into 146
canonical resources. Exactly three canonical resource IDs are multi-type:
`anythingllm-agent-skills`, `pika-mcp-skills`, and
`cline-official-skills-plugins`. They account for four redundant contribution
aliases (and four redundant target-reference aliases); no resource or target
is copied. The verified active baseline remains 615 products, 146 resources,
513 targets, and four stores.

MCP template `evidence.urlField=canonicalSource` is only a research shorthand.
Consumption replaces it with the record's recorded HTTPS canonical source and
removes `urlField` before passing the claim to the shared adapter. No status,
runtime, platform, host, profile, target or permission is inferred.

The existing target fields remain unchanged and no target receives a platform
field. The resource schema is still unbound. In particular, the Ableton
community record keeps its unresolved license and blocked classification.

Before any future separate save authorization, consumers must re-read every
recorded source hash, recompute all resource and target tuple sets, validate
every normalized claim, require profile claims/availability/managed eligibility
to remain zero, and deep-compare all products and stores. Until then rollback
is discarding this candidate.
