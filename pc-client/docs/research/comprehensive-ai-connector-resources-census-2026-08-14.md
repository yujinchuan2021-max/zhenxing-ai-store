## 去重、权限与下一批规则

1. **Identity 顺序**：publisher 控制的 canonical endpoint/repo/manifest > official host listing id > package/version。目录 badge、营销名、tool 名都不参与 publisher 提升。
2. **同实现多宿主**：例如 Airtable/Box/Notion remote MCP 只建一个 Resource，Claude/ChatGPT/Cursor/Codex 都是 CompatibleHost 关系。host-specific sync/app 只有在 publisher manifest、service identity、授权 client 与撤权生命周期均闭合时才可独立；本轮 Dropbox 证据不足以证明三个独立 Resource，故 S02 只建一个 family identity，并记录三种 ConnectionBinding/host surface。
3. **同 provider 多 action**：Zapier/Pipedream/Composio/Make/n8n/Merge/Nango/Workato/Tray/Apify 只建 provider，app/action/workflow 是 capability/target，不复制成“官方 MCP”。
4. **写副作用**：所有 create/update/delete/send/deploy/payment/SQL/infra 操作都需宿主逐次确认或显式管理员策略；`ready-link-only` 不允许 AI Hub 代填 endpoint、headers、env 或 secret。
5. **撤权是双边的**：从 AI host Disconnect 只保证停止宿主调用；OAuth grant、PAT/API key、service account、provider session 仍须在 provider 侧复核/撤销。同步索引和历史聊天按各 host 保留政策另删。
6. **active7/next-major**：`duplicate` 不再进入下一批；`provider-only` 只建立事实关系；`deferred` 必须补齐 exact endpoint/version、auth scopes、write actions、disconnect/token revoke、terms/license 后再审。

1. Dropbox S02：继续确认三种 ConnectionBinding 是否共享 endpoint、authorization client 与 service identity；闭合前保持一个 Resource family，不拆成三个候选。
2. SharePoint ChatGPT app：拆清 user-authenticated 与 admin-managed sync，特别是 `Sites.FullControl.All`、OneDrive 范围和 disconnect 后索引删除。
