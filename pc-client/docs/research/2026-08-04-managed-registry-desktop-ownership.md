# Windows 桌面注册表收据所有权（2026-08-04）

## 决策

Msty Go 与 Letta 使用同一个客户端固定模块 `post-install-registry-receipt`，不为单个厂商编写命令或路径特例。后台只能选择已经进入客户端白名单的产品与模块，不能提供注册表键、可执行路径或卸载命令。

该模块解决的是“可信安装”和“由枕星 AI 安装”之间的区别：仅凭名称、发布者和签名可以识别产品，但不能证明该实例由枕星 AI 发起。没有所有权收据的既有安装继续作为外部安装展示；客户端可以按用户请求打开已经审核的厂商卸载界面，但不得将它冒领为自动管理实例。

## 固定流程

1. 用户确认安装后、启动安装器前，客户端保存当前 Windows 卸载注册表键的基线，并绑定产品、adapter、执行契约、桌面操作 ID 和截止时间。
2. 安装监测只接受基线中不存在且唯一的新卸载键；修改旧键或出现多个新候选都拒绝接管。
3. 新候选必须重新通过名称、发布者、卸载命令形状、安装根目录、主程序路径和卸载器路径检查。
4. 主程序与卸载器必须都位于同一可信安装根下，并分别通过客户端固定的 Authenticode 发布者规则。
5. 成功后原子写入精确注册表键、规范路径、卸载动作和执行契约哈希的收据。以后检测、打开和卸载只使用该精确实例，不能回退到同名候选。
6. 安装取消、超时、收据写入失败、签名失败或注册表扫描不完整时不接管；过期基线永远不能在以后绑定手动安装。
7. 卸载确认精确注册表键和收据绑定的主程序都消失后才删除收据；注册表先删除但主程序仍存在、失败或扫描未知时继续保留收据。
