# CLI agent slice-c official research (2026-08-05)

Scope: only the five `research-pending` products in slice-c: `kortix-cli`, `mini-swe-agent-cli`, `plandex-cli`, `simular-agent-s-cli`, and `agenticseek-cli`. This is a read-only review. No installation, login, service startup, WSL operation, catalog change, state change, or code change was performed.

## Decision summary

No Windows managed-install profile is approved. None of the five has a fixed, self-contained Windows artifact with a sufficiently narrow install/runtime/teardown contract for the current AI Hub drivers.

| product | official Windows/install shape | fixed artifact / hash | terminal start | decision and blocker |
|---|---|---|---|---|
| `kortix-cli` | Kortix's official repository describes a shell installer and a multi-service local/server deployment. The repository's documented Windows route is not a native standalone CLI contract; the product needs Docker/services and persistent configuration. | No verified fixed Windows CLI artifact or official hash. The official Windows EXE releases are Kortix Desktop, not this CLI. | `kortix start`, `stop`, `restart`, `logs`, `status`, `update`, `reset` after the service stack is installed. | **blocked / manual only**. Do not treat the Desktop EXE as a CLI installer; do not run the dynamic shell installer from the Windows driver. Docker, services, secrets, and `reset` data ownership are outside the current receipt contract. |
| `mini-swe-agent-cli` | Official repository offers `uvx mini-swe-agent`, `pip install mini-swe-agent`, or source installation. No Windows-specific binary is published. The agent's execution model is Bash; official material also documents Docker/Podman and other environment backends. | Python package identity is `mini-swe-agent`; the official repository showed the current v2 line, but no fixed Windows binary. No official Windows hash found. | `mini` after package installation; anonymous path uses `uvx mini-swe-agent`. | **blocked**. A Python venv alone does not establish the required Bash/container semantics, and the current Windows driver has no accepted shell adapter. Keep as official tutorial/manual guidance. |
| `plandex-cli` | Official README explicitly says Windows works only in WSL and does not work in Windows CMD or PowerShell. Local/self-hosted mode additionally uses Docker; cloud is no longer accepting new users. | Official release `cli/v2.2.1` exists, but no approved native Windows artifact or hash was verified for this slice. The install path is a shell script/WSL flow. | `plandex` or `pdx` in the supported WSL shell. | **blocked / WSL and service dependent**. Existing `wsl-managed` cannot own the WSL binary, Docker-backed server/state, secrets, update behavior, and data lifecycle as one safe receipt. |
| `simular-agent-s-cli` | Official Agent-S repository provides a Python framework/console package and Windows setup material, but the project is a computer-use agent requiring desktop control, OCR, model/grounding endpoints, and platform dependencies. | PyPI package identity observed in official project materials as `gui-agents`; no fixed Windows bundle or official hash verified. | Official project usage is through the Agent-S Python console/framework entry point after environment setup. | **blocked / high risk**. It is a genuine CLI/framework, not a desktop installer, but a plain Python profile cannot safely own GUI permissions, OCR/Tesseract/Paddle dependencies, model services, arbitrary local execution, or teardown. |
| `agenticseek-cli` | Official repository documents a source checkout, Python 3.10.x recommendation, Docker Engine/Compose services, Windows `install.bat`, and Windows service startup. CLI mode still requires the service stack and repository configuration. | No fixed standalone Windows CLI package, image digest, or official hash verified. | `uv run cli.py` after installation and required services are running. | **merge/reclassify, not managed CLI**. This is a CLI mode of the self-hosted project rather than a separately distributed CLI product. Docker/Redis/SearxNG/frontend/backend, model configuration, workspace paths, and secrets exceed the current single-package receipt. Keep the existing self-hosted/tutorial identity and avoid a duplicate installable CLI card. |

## Official evidence

- Kortix official repository: <https://github.com/kortix-ai/suna>. It documents `curl -fsSL https://kortix.com/install | bash`, the `kortix` service commands, and a Docker/service-oriented local or server setup. The repository also distinguishes the broader Kortix application from the CLI management surface.
- mini-SWE-agent official repository: <https://github.com/SWE-agent/mini-swe-agent>. It documents `uvx mini-swe-agent`, `pip install mini-swe-agent`, `mini`, and the Bash-only tool model; the same repository documents Docker/Podman and other execution environments.
- Plandex official repository: <https://github.com/plandex-ai/plandex>. Its README states that Windows is supported through WSL only and that CMD/PowerShell are unsupported; it documents `plandex`/`pdx`, the shell install path, Docker local mode, and release `cli/v2.2.1`.
- Agent-S official repository: <https://github.com/simular-ai/Agent-S>. It identifies Agent S as a computer-use framework and contains the Python package/setup and OSWorld/Windows-related setup material. The project is not a fixed native Windows CLI bundle.
- AgenticSeek official repository: <https://github.com/Fosowl/agenticSeek>. It documents Git checkout, Python 3.10.x, Docker Engine/Compose, Windows batch setup/service commands, and `uv run cli.py`; it describes CLI mode as part of the self-hosted stack.

## Explicit exclusions

No dynamic `curl | bash` or `iwr | iex` installer was executed or promoted as a managed action. No third-party tutorial, unofficial mirror, guessed package, guessed artifact URL, or unverified checksum was used. Because no fixed verified Windows download was found for these five, the JSON artifact fields are `null`.
