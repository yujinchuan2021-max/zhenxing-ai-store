# Windows 桌面产品认证

更新时间：2026-08-01

## 范围

客户端当前有 27 个 Windows 托管安装产品：目录中的 26 个 `desktop-reviewed` 产品，加上按本地模型模块管理的 Ollama。后台只记录认证状态，真正的下载源、哈希、签名者、安装检测、打开和卸载策略仍由客户端本地白名单决定。

## 三种状态

| 状态 | 含义 | 发布安装能力 |
| --- | --- | --- |
| 待审核 | 没有匹配当前完整执行契约的本地审核，或被运营人员主动冻结 | 禁止 |
| 已审核 | 下载、适配器和生命周期已绑定到当前本地审核哈希 | 允许 |
| 已实机验收 | 同一执行契约已在真实 Windows 账户完成全生命周期验收 | 允许 |

完整执行契约包含产品注册、下载计划、桌面适配器和生命周期策略。签名者、发布者、程序名、卸载器、卸载参数或数据保留策略任一变化，哈希都会变化，旧实机验收自动失效。

## 后台操作

在“产品管理”选择托管桌面产品即可查看认证卡片。实机验收必须填写验收人、客户端版本、Windows 版本、证据位置，并逐项确认：

- 下载与完整性
- 安装器调起
- 安装后检测
- 打开
- 更新归属
- 卸载
- 用户数据保留

每次状态变化都追加历史记录。退回待审核不会删除旧事实，但会立即阻止该产品继续发布安装能力。后台输入不接受下载地址、命令或执行参数，不能借认证状态创建新的本地执行能力。

本地记录保存在 `admin/data/product-acceptance.local.json`。该文件不进入 Git；Docker 本地后台通过已有 `admin/data` 挂载持久化。
