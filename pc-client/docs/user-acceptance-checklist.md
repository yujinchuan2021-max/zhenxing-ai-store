# AI Hub PC 用户验收清单

本清单只记录需要在真实日常 Windows 账户下由用户亲自确认的行为。自动化测试通过不能替代这些结果。

## 一、AI Hub 客户端

- [ ] 双击 `release-local-server-client\AI-Hub-Local-0.1.22-Windows-x64-Setup.exe`，安装界面正常显示中文和安装路径。
- [ ] 安装完成后能从桌面和开始菜单启动。
- [ ] 关闭主窗口后，托盘图标仍存在。
- [ ] 从托盘重新打开主窗口，页面和任务状态保持正常。
- [ ] 从 Windows“已安装的应用”卸载后，程序目录和快捷方式消失。

## 二、账号与社区

- [ ] 输入真实可用邮箱后能收到验证码；本地 Mailpit 只算开发验证，不算公网邮件验收。
- [ ] 完成注册、退出、重新登录。
- [ ] 修改昵称、头像或简介后重新启动客户端，资料仍正确。
- [ ] 使用当前密码和新邮箱验证码完成邮箱换绑，并可用新邮箱重新登录。
- [ ] 修改手机号后重启客户端，个人中心显示正确。
- [ ] 修改密码后其他设备退出，旧密码不能登录。
- [ ] 在设备会话中撤销另一个会话，被撤销设备不能继续刷新登录。
- [ ] PC 右上角能显示账号与社区提醒未读数，并可在个人中心统一标为已读。
- [ ] 社区原生关注和喜欢能分别出现在个人中心的收藏与喜欢列表。
- [ ] 点击社区时未登录用户先进入登录流程。
- [ ] 已登录用户点击社区后，Flarum 直接显示在 PC 内，不打开系统浏览器，也不再要求输入社区密码。
- [ ] 能发帖、回复、刷新页面并再次访问自己的内容。
- [ ] 在社区中收藏和喜欢讨论后，个人中心对应列表可以打开该讨论。

## 三、目录与外部链接

- [ ] 首页第一层展示厂商，不以产品分类代替厂商。
- [ ] “全部厂商”进入厂商目录，分类筛选只出现在目录内容区域。
- [ ] Web 产品直接打开产品网站。
- [ ] 普通桌面产品只打开厂商官方下载页面。
- [ ] 教程打开该厂商对应的教程地址。

## 四、已审核桌面产品

每个准备托管下载的产品都单独复制本段并记录版本、下载源、SHA-256 和发布者。

- [ ] 点击安装前没有提前扫描环境或发起下载。
- [ ] 点击后先探测官方源；官方源失败时才尝试批准的国内镜像。
- [ ] Clash 开启与关闭两种情况下，下载策略和错误提示都符合预期。
- [ ] 下载可暂停、恢复和取消，重启客户端后任务状态可恢复。
- [ ] 校验失败时绝不打开安装器。
- [ ] 校验通过后直接打开已下载的安装器。
- [ ] 安装器打开不立即显示“已安装”。
- [ ] 完成安装后固定探针识别出正确版本。
- [ ] 卸载只使用匹配厂商、产品和安装目录的可信卸载项。

首批产品：

- [ ] ChatGPT Desktop：确认下载并打开的是 Microsoft 签名的 Store 官方安装引导器；Store 安装后识别为当前主应用 `9PLM9XGG6VKS` / `OpenAI.Codex`，不能把引导器本身误判为已安装。
- [ ] Claude Desktop：确认普通用户 x64 EXE 下载、`Anthropic, PBC` 签名、安装后 `Claude` 探针和厂商自动更新；不得误用企业 MSIX。
- [ ] Comfy Desktop：确认当前 NSIS 启动器与 `Comfy Desktop` 探针；卸载后 `%USERPROFILE%\ComfyUI-Installs`、`%USERPROFILE%\ComfyUI-Shared` 和 `%APPDATA%\Comfy Desktop` 仍保留。
- [ ] Ollama：确认 `OllamaSetup.exe`、用户级安装、版本探针和交互式卸载；模型目录是否删除必须由用户明确选择。

## 五、CLI 产品

- [ ] Codex CLI 在依赖满足时一键部署，失败信息能指向具体依赖或网络阶段。
- [ ] Claude Code 在依赖满足时一键部署，并能通过版本探针确认。
- [ ] Gemini CLI 在依赖满足时一键部署，并能通过版本探针确认。
- [ ] 客户端只卸载自己有安装收据和所有权标记的 CLI，不删除用户手工安装的同名包。
- [ ] 修改 CLI 安装目录后，旧安装仍按收据中的真实路径管理。
