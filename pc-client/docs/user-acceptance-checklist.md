# 枕星 AI PC 用户验收清单

本清单只记录需要在真实日常 Windows 账户下由用户亲自确认的行为。自动化测试通过不能替代这些结果。

## 一、AI Hub 客户端

- [ ] 双击 `release-local-server-client\AI-Hub-Local-0.1.26-Windows-x64-Setup.exe`，安装界面正常显示中文和安装路径。
- [ ] 安装完成后能从桌面和开始菜单启动。
- [ ] 关闭主窗口后，托盘图标仍存在。
- [ ] 从托盘重新打开主窗口，页面和任务状态保持正常。
- [ ] 从 Windows“已安装的应用”卸载后，程序目录和快捷方式消失。

## 二、账号与社区

- [ ] 输入真实可用邮箱后能收到验证码；本地 Mailpit 只算开发验证，不算公网邮件验收。
- [ ] 完成注册、退出、重新登录。
- [ ] 修改昵称、头像或简介后重新启动客户端，资料仍正确。
- [ ] 使用当前密码和新邮箱验证码完成邮箱换绑，并可用新邮箱重新登录。
- [ ] 修改手机号后重启客户端，个人中心显示正确。
- [ ] 修改密码后其他设备退出，旧密码不能登录。
- [ ] 在设备会话中撤销另一个会话，被撤销设备不能继续刷新登录。
- [ ] PC 右上角能显示账号与社区提醒未读数，并可在个人中心统一标为已读。
- [ ] 社区原生关注和喜欢能分别出现在个人中心的收藏与喜欢列表。
- [ ] 点击社区时未登录用户先进入登录流程。
- [ ] 已登录用户点击社区后，Flarum 直接显示在 PC 内，不打开系统浏览器，也不再要求输入社区密码。
- [ ] 能发帖、回复、刷新页面并再次访问自己的内容。
- [ ] 在社区中收藏和喜欢讨论后，个人中心对应列表可以打开该讨论。

## 三、目录与外部链接

- [ ] 首页第一层展示厂商，不以产品分类代替厂商。
- [ ] “全部 AI 厂商”只展示拥有已启用 AI 工具产品的厂商，并且厂商页只显示其 AI 工具产品。
- [ ] “全部 AI 可接入厂商”只展示拥有已启用 AI 可接入产品的厂商，并且厂商页只显示其接入相关产品。
- [ ] 同一厂商同时出现在两个目录时，名称、图标、官网和基础资料一致，但两个页面的产品不串页。
- [ ] 产品详情页不再显示 Skill/MCP 扩展子目录。
- [ ] Skill、MCP、插件和连接器分别从左侧独立商店进入，并按“目标工具 → 资源列表 → 单项详情”展开；工具卡同时显示厂商与产品。
- [ ] 同一资源支持多个类型或目标产品时，各入口显示相同资源身份和版本，不出现后台副本。
- [ ] Web 产品直接打开产品网站。
- [ ] 普通桌面产品只打开厂商官方下载页面。
- [ ] 教程打开该厂商对应的教程地址。

## 四、已审核桌面产品

每个托管产品都必须单独记录版本、下载源、SHA-256、发布者和真实操作结果。后台“产品管理”中的认证卡片是统一记录入口。

27 个本地托管产品已通过当前执行契约审核，状态均为“已审核”；这不等于实机验收。以下复选框只记录用户日常账户下的真实安装行为。

- [ ] 点击安装前没有提前扫描环境或发起下载。
- [ ] 点击后先探测官方源；官方源失败时才尝试批准的国内镜像。
- [ ] Clash 开启与关闭两种情况下，下载策略和错误提示都符合预期。
- [ ] 下载可暂停、恢复和取消，重启客户端后任务状态可恢复。
- [ ] 校验失败时绝不打开安装器。
- [ ] 校验通过后直接打开已下载的安装器。
- [ ] 安装器打开不立即显示“已安装”。
- [ ] 完成安装后固定探针识别出正确版本。
- [ ] 卸载只使用匹配厂商、产品和安装目录的可信卸载项。

专项约束：

- [ ] ChatGPT Desktop：实际完成 Store 安装、主应用 `9PLM9XGG6VKS` / `OpenAI.Codex` 识别、首次启动和卸载；不能把引导器本身误判为已安装。
- [ ] Claude Desktop：实际运行已审核的普通用户 x64 EXE，确认安装后 `Claude` 探针和厂商自动更新；卸载必须打开厂商交互式 UI，注册命令中的 `-s` 不得被执行；不得误用企业 MSIX。
- [ ] Comfy Desktop：旧 ComfyUI Desktop V1 只能显示迁移提示，不能显示为当前版“已安装”；当前版仍需独立完成安装、打开和卸载验收。
- [ ] Comfy Desktop：实际完成安装、探针和卸载，并确认 `%USERPROFILE%\ComfyUI-Installs`、`%USERPROFILE%\ComfyUI-Shared` 和 `%APPDATA%\Comfy Desktop` 仍保留。
- [ ] Ollama：实际完成用户级安装、版本探针和交互式卸载；模型目录是否删除必须由用户明确选择。
- [ ] GPT4All：卸载必须调用 Qt Installer Framework 的 `maintenancetool.exe`，不得按 Inno 卸载器处理。
- [ ] OpenClaw Windows Hub：卸载必须显示厂商交互界面，由用户决定 Gateway 与状态数据；不得执行静默全清理。
- [ ] NVIDIA AI Workbench：先验证桌面应用可独立安装；只有用户选择 Full Local 时才检查 WSL、容器和 Git。
- [ ] 完成任一产品后，在后台产品认证卡片勾选七项并填写证据位置；未完成的产品不得标记为“已实机验收”。

## 五、CLI 产品

- [ ] Codex CLI 在依赖满足时一键部署，失败信息能指向具体依赖或网络阶段。
- [ ] Claude Code 在依赖满足时一键部署，并能通过版本探针确认。
- [ ] Gemini CLI 在依赖满足时一键部署，并能通过版本探针确认。
- [ ] 客户端只卸载拥有有效收据，或能按本地白名单精确恢复可信身份的 CLI；不删除身份、版本或路径不匹配的用户手工安装内容。
- [ ] 修改 CLI 安装目录后，旧安装仍按收据中的真实路径管理。
