# 全部 AI 可接入厂商频道：第一轮只读审计

审计日期：2026-08-05  
审计范围：`pc-client/admin/data/catalog-v1.json`、目录类型定义、前端频道筛选及后台校验代码。  
本轮仅产出候选与缺口，不修改共享前端，不调用 `saveDraft`，不发布。

## 1. 当前基线

| 项目 | 数量/结论 |
| --- | ---: |
| 厂商 | 375 |
| 一级产品 | 614 |
| `ai-tool` 产品 | 458 |
| `ai-connectable` 产品 | 156 |
| 含接入类产品的厂商 | 128 |
| 生态资源 | 146 |

现有结构已具备“单份厂商资料、产品通过 `directoryKind` 分频道”的基础；前端在打开 AI 厂商页和可接入厂商页时分别传入 `ai-tool` / `ai-connectable`，同一厂商资料可以复用。

## 2. 需要优先复核的候选

### A. 接入频道疑似混入桌面产品

156 个接入产品中有 65 个属于 `desktop-reviewed` 或 `desktop-official`，另有 1 个 `cli-official`，没有 `local-model`。这些条目应逐项确认：它们是否确实代表厂商的 API、模型服务、开发平台或可被 AI 接入的云能力；如果只是桌面软件，应回到 `ai-tool` 或交由 AI 厂商桌面岗位处理。

优先复核代表性条目：

- Google Chrome、Android Studio
- Microsoft Visual Studio、Microsoft Edge
- Unity 6、Unreal Engine、Roblox Studio
- Figma、Affinity、Blender、DaVinci Resolve
- Docker Desktop、Postman、MongoDB Compass、Redis Insight
- Linear、Slack、Asana、monday、ClickUp、Miro、Zoom
- Ableton Live、OBS Studio、Audacity、Streamlabs Desktop
- AnyDesk、向日葵远程控制 Windows 版
- Airtable、Obsidian、Anytype、Box

这不是直接删除清单，而是“官方接入能力证据复核清单”。在没有厂商官网/官方文档/官方仓库证据前，不应把桌面产品名称当作接入产品名称。

### B. 频道分类已经有实用行业维度，但需要补齐关系语义

接入频道已有游戏开发、视频创作、音频制作、远程控制、编程与调试、办公自动化、数据库与数据、文档与知识库、云服务与运维等分类。现有数量较少、值得后续按官方能力复核的分类包括：

- 远程控制：2
- 视频创作：4
- 音频创作/音频制作：各 2
- 直播与录制：2
- 智能设备：1
- 营销与搜索：1
- 网站与建站、内容管理与发布、地图与地理空间：各 2

缺口不是简单新增“AI 接入工具”分类，而是为每个产品补充可核验的具体能力，例如 API、官方 MCP、Webhook、OAuth、SDK、模型调用、媒体生成/处理、远程控制接口、开发者平台或企业连接器，并保留与厂商一级产品的关系。

## 3. 数据模型缺口

当前 `Product` 类型和目录记录包含 `directoryKind`、`category`、官网、教程、安装策略等字段，但没有产品级的：

- 官方来源证据类型及 URL（官网产品页、官方 API 文档、官方仓库等）；
- 接入类型（API、SDK、MCP、OAuth、Webhook、OpenAI-compatible 等）；
- 接入目标/能力（文本、图像、视频、音频、游戏、办公、远程控制、开发等）；
- 与厂商产品的明确关系（一级产品、开发者平台、API 服务、官方 MCP 入口）；
- 官方能力的最后核验时间与核验备注。

因此本轮不能仅凭现有 `website` / `tutorial` 字段判定“已证明可接入”。第三方页面、搜索摘要和推测 URL 不可作为补证。

## 4. 后台 CRUD 与去重审计结论

- 目录本身未发现重复产品 ID；但当前审计只能确认 ID 唯一，不能证明同一官方产品被不同名称重复收录。
- `directoryKind` 已存在且前端按频道过滤，具备展示隔离基础。
- 需要把“同一厂商资料复用”和“按频道复制产品记录”区分开：厂商实体只保留一份，产品实体也应保留单一 ID，通过频道字段或明确关系投影展示。
- 后台审核规则应在保存前检查产品 ID、厂商 ID、官方来源、目录层级和接入类型；本轮不改变现有校验实现。
- 不应在后台增加任意命令下发、密钥/令牌/密码字段或收集流程。

## 5. 后续候选队列（不执行）

1. 对上述 65 个桌面型接入候选逐条做一手来源复核，确认“桌面产品”与“可接入能力”是否为同一条目；必要时拆成同厂商下的 API/平台产品。
2. 为 156 个接入产品建立官方证据与接入类型补录表，证据只接受厂商官网、官方文档、官方仓库。
3. 统一“音频创作/音频制作”等分类命名，并保持按行业特性细分，不退回单一“AI 接入工具”。
4. 对 128 家接入厂商做跨厂商重复语义检查：厂商只复用一份资料，产品按官方产品身份去重。
5. 完成复核后，再由后台负责人决定是否形成草稿；本轮不 `saveDraft`、不发布。

## 结论

当前目录具备基本的厂商复用与频道隔离结构，产品 ID 没有发现重复；主要风险是接入频道存在大量桌面产品混入，以及产品级官方来源和接入关系无法从现有字段充分证明。建议先完成证据/关系复核，再进行任何 CRUD 变更。
