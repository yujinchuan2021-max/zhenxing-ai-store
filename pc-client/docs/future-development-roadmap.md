# 枕星 AI 长期待开发路线图

更新时间：2026-08-02

## 文档用途

本文件只记录已经讨论并确认保留、但不属于当前版本交付范围的能力。当前已实现内容以 [开发状态](development-status.md) 为准；不可逆架构决定以 `docs/adr/` 为准；真实设备是否通过以用户验收记录为准。

当某项开始开发时，先检查它与现有目录、身份、社区、安装和发布能力是否并存，再把状态改为 `in-progress`。完成并通过相应验收后，将实现结果写入开发状态，本文件保留条目并改为 `done`，不删除历史。

## 状态词汇

| 状态 | 含义 |
| --- | --- |
| `approved-deferred` | 产品方向已确认，明确留给后续版本 |
| `needs-research` | 方向成立，但真实产品结构或安全边界仍需一手资料研究 |
| `blocked-external` | 需要服务器、证书、服务商、付款或其他外部条件 |
| `continuous` | 没有一次性终点，需要持续维护 |
| `in-progress` | 已进入当前开发范围 |
| `done` | 已实现并完成规定验收 |
| `superseded` | 已被新的明确决定取代，并保留取代依据 |

## 不得被后续版本破坏的边界

1. catalog schema v2 中厂商只有一份；产品以单值 `directoryKind` 进入“全部 AI 厂商”或“全部 AI 可接入厂商”。
2. 产品不保存扩展子目录。生态资源位于顶层 `resources`，社区、商店和未来 AI 接口引用同一个 `resourceId + version`。
3. 资源来源产品与目标产品是两种关系；兼容某个 AI 工具不等于归属于该工具的厂商。
4. 后台、社区内容和外部 AI 都不能向 PC 下发任意命令、脚本、包名、URL、配置片段或本地路径。
5. 本地变更只能由客户端固定模块与审核配置执行，必须由用户确认、保存所有权收据，并只回收枕星 AI 自己写入的内容。
6. Flarum 继续负责讨论、回复、通知、关注和喜欢；用户、凭据、联系方式和设备会话继续由统一身份服务负责。
7. 自动化通过不等于第三方安装器、真实账号、真实网络、真实支付或用户日常 Windows 账户已经验收。

## 延期功能

### ECO-001：枕星 AI 资源 MCP

- **状态**：`approved-deferred`
- **用户价值**：Codex、Claude Code 和其他兼容 AI 工具可以直接搜索、筛选、比较枕星 AI 的资源目录，而不是让用户自己在互联网中反复寻找。
- **范围**：提供资源搜索、类型筛选、目标产品兼容性、来源、审核状态、权限、地区可用性、版本和风险说明；返回结构化资源与安装意图。
- **依赖**：稳定的 schema v2 资源 ID/版本、资源审核状态、兼容关系、远程身份和限流、公开 HTTPS 服务。
- **并存与冲突**：MCP 与 PC、网站和商店读取同一目录；不能建立第二套资源数据库。AI 只能创建安装意图，不能绕过 PC 直接执行。
- **安全边界**：查询与比较默认只读；任何安装、授权、文件写入或进程启动都必须回到 PC，由固定模块重新校验并让用户确认。
- **验收标准**：至少两个独立宿主完成搜索与比较；伪造资源 ID、过期版本、越权目标和命令注入全部被拒绝；用户未确认时设备保持零变更。

### COMMUNITY-001：社区帖子引用结构化资源

- **状态**：`approved-deferred`
- **用户价值**：用户浏览社区时，可以从教程或案例帖子直接查看并安装作者引用的 Skill、MCP、插件或工作流。
- **范围**：帖子引用产品和不可变资源版本；帖子展示统一资源卡、审核状态、适用产品和“安装”入口；资源详情和商店可反向进入相关讨论。
- **依赖**：资源发布与版本模型、Flarum 扩展或受限桥接接口、统一身份、PC 安装意图协议。
- **并存与冲突**：帖子正文不是可执行资源。Flarum 只保存讨论和资源引用，结构化资源、版本、审核状态和安装数据由目录/资源服务持有。
- **安全边界**：编辑帖子不能静默替换已发布资源版本；被撤回或审核失败的版本不能新装，但已安装内容仍可在 PC 管理。
- **验收标准**：用户可从社区、资源商店和个人主页打开同一资源；三个入口显示相同版本与审核状态；帖子修改不会改变已安装版本。

### WORKFLOW-001：单产品工作流包与自动导入

- **状态**：`approved-deferred`
- **用户价值**：用户看到优秀的 ComfyUI 等软件工作流后，可以先补齐环境和依赖，再一键导入并打开，而不是手工寻找节点、模型和路径。
- **范围**：以 ComfyUI 为首个目标，支持工作流文件、封面、说明、目标软件版本、自定义节点、模型、Python 依赖、素材、硬件要求和导入位置；安装完成后启动目标软件并打开工作流。
- **依赖**：资源版本、目标产品适配器、依赖清单格式、模型/节点来源与许可、下载和磁盘预检、可恢复安装收据。
- **并存与冲突**：工作流是独立资源类型，不等同于 Skill，也不能作为产品重复计数。已有 ComfyUI 安装和用户手工节点必须被识别并保留。
- **安全边界**：不得直接执行帖子中的脚本；自定义节点按可执行代码等级审核；第三方模型和素材必须记录许可证与来源；卸载只移除收据拥有的内容。
- **验收标准**：在干净环境、已有 ComfyUI、部分依赖已存在和安装中断四种场景下均能给出正确计划；成功后工作流可在目标软件打开；卸载不损坏用户原有工作流。

### WORKFLOW-002：多产品工作流编排

- **状态**：`approved-deferred`
- **用户价值**：动漫制作等方案可以组合 ComfyUI、Blender、剪辑软件和多个生态资源，用户无需逐项理解安装顺序。
- **范围**：有向步骤图、产品与环境依赖、阶段状态、输入输出、暂停/继续、失败恢复、部分重试、版本锁定和最终启动入口。
- **依赖**：WORKFLOW-001、统一产品状态、环境模块、跨产品安装收据、磁盘预算、资源版本冻结。
- **并存与冲突**：编排器只能组合现有固定动作，不能把后台流程描述解释成任意命令；已经安装的产品与资源优先复用，不重复接管用户内容。
- **安全边界**：每个高风险步骤单独展示权限和来源；失败回滚只撤销本次编排拥有的变更；账号登录、密钥和付费下载必须由用户完成。
- **验收标准**：支持至少一个三产品真实方案；中途退出后可恢复；任一步失败时能准确保留或回滚；不得删除流程开始前已有内容。

### CREATOR-001：创作者资源发布与版本管理

- **状态**：`approved-deferred`
- **用户价值**：开发者可以把成熟的 Skill、MCP、插件和工作流发布成可发现、可审核、可持续更新的资源。
- **范围**：草稿、提交审核、来源证明、版本、变更说明、兼容目标、权限、许可证、撤回、举报、复制并改编、作者主页和资源统计。
- **依赖**：统一身份、资源服务、对象存储、审核队列、安全扫描、人工复核、版本不可变策略。
- **并存与冲突**：社区昵称用于公开展示，收款身份不公开；帖子与资源分离；更新生成新版本，不能覆盖已安装版本。
- **安全边界**：自动扫描通过不等于安全认证；可执行资源仍需目标级客户端审批；密钥和用户凭据禁止进入资源包。
- **验收标准**：完整覆盖发布、驳回、修订、升级、撤回、举报和派生来源；历史版本和作者归属可追溯。

### COMMERCE-001：付费资源与赞赏

- **状态**：`approved-deferred`
- **用户价值**：优秀开发者可以选择免费、免费并接受赞赏、付费解锁或付费后接受额外赞赏。
- **范围**：商品、价格、订单、权益、优惠、退款、争议、赞赏、创作者结算、提现、发票/税务提示和区域可售范围。
- **依赖**：CREATOR-001、生产身份与风控、支付服务商、创作者收款身份验证、服务条款、隐私政策、内容和许可证审核。
- **并存与冲突**：资源技术身份、商品和购买权益必须分离；修改价格不改变资源文件，更新资源不抹掉用户已经购买的版本。云厂商账单不得与枕星 AI 用户付款混为一谈。
- **安全边界**：付费不跳过安全审核；未购买的 AI 只能看到公开介绍；支付回调不能直接触发本地执行；第三方模型、素材和代码无转售许可时不得打包收费。
- **验收标准**：免费、付费、赞赏、退款和版本升级权益账目一致；重复回调幂等；未授权下载被拒绝；结算和审计记录可追溯。

### ECOSYSTEM-002：更多生态资源类型

- **状态**：`approved-deferred`
- **用户价值**：在 Skill、MCP 和插件之外，逐步收录连接器、工作流、Agent 模板、提示词模板、规则、命令、Hook、知识包和开发组件。
- **范围**：每种类型先定义明确边界、宿主能力、权限、版本、展示方式、安装/导入方式和卸载所有权，再决定是否增加独立商店。
- **依赖**：schema 后续版本设计、真实宿主产品研究、固定适配器和安全审计。
- **并存与冲突**：不能仅为增加一个导航项就把不同执行风险的资源塞进同一安装模块；没有真实内容的商店默认不展示。
- **安全边界**：新增展示类型可以通过目录升级；新增本地执行原语必须升级 PC。Hook、命令和开发组件默认按高风险可执行代码处理。
- **验收标准**：每种启用类型都有独立 schema 校验、权限说明、至少一个真实目标适配器、安装与精确卸载回归。

### CATALOG-001：AI 与 AI 可接入产品持续扩充

- **状态**：`continuous`
- **用户价值**：维持“资源大而全”，持续补齐新厂商、新产品及传统软件的 AI 接入能力。
- **范围**：官方来源扫描、人工归属确认、AI 工具/AI 可接入职责判断、Windows 入口、生命周期变化、资源来源与兼容目标。
- **依赖**：官方一手资料、候选审核流程、目录签名发布和历史版本。
- **并存与冲突**：自动抓取只生成候选，不直接发布或获得执行许可；同一厂商不重复建档，同一产品不因多个入口重复计数。
- **安全边界**：第三方下载站、搜索摘要和未经核实的社区说法不能作为安装依据。
- **验收标准**：每轮保留来源、审核结论和拒绝理由；目录更新后 PC 无需重新打包即可显示；本地执行能力仍由独立审批决定。

### DESKTOP-001：桌面产品逐项受管生命周期审核

- **状态**：`needs-research`
- **用户价值**：把当前只打开厂商官方下载页的产品，在证据充分时逐步升级为可检测、下载、校验、打开和管理的受管产品。
- **范围**：当前第二轮 79 个 Windows 图形产品，以及后续新增桌面产品的来源、签名、下载、安装、检测、打开、更新、卸载和数据保留审计。
- **依赖**：官方安装包、客户端固定注册项、审批资料卡、隔离 Windows 环境和用户日常账户验收。
- **并存与冲突**：不能把一个厂商的安装逻辑复制给另一个产品；厂商更改安装器后旧审批自动失效；普通桌面产品可继续安全降级为官方下载入口。
- **安全边界**：未通过完整执行契约审核的产品不得显示受管安装；自动化不能运行或代表第三方安装器人工验收。
- **验收标准**：每个产品分别记录七项真实 Windows 行为证据，并能在后台区分待审核、已审核和已实机验收。

### CLI-001：CLI 覆盖与延期模块

- **状态**：`needs-research`
- **用户价值**：在桌面产品收口后继续补齐 CLI，并为安全的一键部署、命令窗口启动和精确卸载提供一致体验。
- **范围**：Codex CLI、Claude Code、Gemini CLI 的真实网络/权限验收，以及 Cursor WSL、Hermes Agent、OpenCode 平台包等已有研究但尚未批准的模块。
- **依赖**：官方分发身份、运行时版本、WSL 环境、固定包/哈希/签名、更新策略、配置和凭据边界。
- **并存与冲突**：CLI 始终是独立一级产品，不能合并到可视化产品入口；WSL 是环境或复合产品组件，不能冒充普通 Windows 客户端。
- **安全边界**：不执行可变远程 bootstrap；不开放任意 npm/pip 参数；卸载只处理模块目录、shim、PATH 和收据拥有内容。
- **验收标准**：真实网络、代理、权限、安装、启动、更新和卸载全部通过；用户账号、会话、Skill、MCP 和项目数据按产品契约保留。

### WEB-001：公共官网

- **状态**：`approved-deferred`
- **用户价值**：提供品牌介绍、客户端下载、公开目录浏览、帮助和社区入口；PC 仍是安装与本地管理主产品。
- **范围**：`zhenxingai.com` 官网、客户端下载、目录只读展示、帮助、隐私与服务条款、社区入口和状态页面。
- **依赖**：生产域名、HTTPS、发布服务、公开目录 API、品牌素材和合规文档。
- **并存与冲突**：网站只浏览和跳转，不复制 PC 本地安装逻辑；需要安装时引导打开枕星 AI PC。
- **安全边界**：官网不能向浏览器下发本地执行命令；下载必须绑定签名清单、文件大小和哈希。
- **验收标准**：移动端与桌面端可访问；下载来源可验证；目录与 PC 使用同一活动版本；无本地能力时不伪装安装成功。

### ACCOUNT-001：生产账号与个人数据能力

- **状态**：`approved-deferred`
- **用户价值**：在公开运营前提供完整的用户数据控制和合规能力。
- **范围**：用户注销、个人数据导出、数据删除与保留策略；手机号短信验证继续作为后续能力，当前注册登录保持邮箱和密码。
- **依赖**：正式邮件/短信服务商、隐私政策、服务条款、审计日志、备份删除策略和客服流程。
- **并存与冲突**：统一身份仍是唯一用户来源；不能在 Flarum 或未来支付系统建立第二套登录密码。
- **安全边界**：敏感操作要求重新认证、速率限制和可撤销会话；删除流程必须覆盖身份映射但保留依法必须保存的交易记录。
- **验收标准**：导出完整、删除可验证、社区映射正确处理、其他设备会话失效、审计记录不泄露凭据。

### OPS-001：正式服务器与发布运营

- **状态**：`blocked-external`
- **用户价值**：把当前 Docker 本地环境迁移为可运营、可监控、可恢复的正式服务。
- **范围**：生产服务器、`zhenxingai.com` 子域、正式 TLS、SMTP、数据库备份与恢复、监控告警、灾备、生产密钥托管、发布审批、外部安全评估和 Windows 代码签名。
- **依赖**：服务器与服务商账号、域名解析、证书、代码签名证书、预算和生产运维责任人。
- **并存与冲突**：本地 Docker 继续用于开发验收，不能把本地证书、默认密钥、Mailpit 或回环地址带入生产；云服务账单与未来用户支付独立。
- **安全边界**：生产私钥不进入镜像、仓库、客户端或公开发布目录；正式通道保持禁用直到全部外部条件通过。
- **验收标准**：备份恢复演练、告警演练、密钥轮换、签名制品、旧版升级、SmartScreen 和公网邮件送达全部真实通过。

## 开发前冲突检查

每次从本文件选择新功能开发时，至少回答：

1. 它使用现有厂商、产品、资源和用户身份，还是错误地创建了重复实体？
2. 它与现有产品入口、CLI 独立展示、双目录视图和资源商店如何并存？
3. 它写入哪些本地文件或远程数据，谁拥有，如何记录收据和精确撤销？
4. 它是否引入新的执行原语？若是，必须升级客户端并新增审批，不能只改后台。
5. 旧功能需要保留、迁移还是删除？被取代的页面、字段、兼容分支和测试必须一起清理，不能长期双写。
6. 自动验证、隔离环境验收、真实用户设备验收和生产验收分别需要什么证据？
