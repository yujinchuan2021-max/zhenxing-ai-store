# 枕星 AI 统一安装协议

## 目标

所有现有产品和后续新增厂商都通过同一套产品行为解析和安装入口工作。目录数据负责描述产品，客户端本地注册表负责批准可执行的安装能力。

## 产品行为

每个产品只能落入以下一种模式：

| 模式 | 用户主操作 | 客户端行为 |
| --- | --- | --- |
| `direct-open` | 打开产品 / 打开教程 | 直接打开经过目录校验的网站 |
| `official-installer-page` | 获取官方安装包 | 打开厂商官方下载页，不执行本地安装 |
| `managed-cli` | 一键安装 | 自动检测依赖，使用本地批准的包和参数部署，随后验证版本 |
| `managed-installer` | 一键安装 | 自动检测依赖，下载白名单安装包，校验签名或哈希，下载完成后打开安装器并检测结果 |

前端不按厂商分别实现按钮和流程。所有产品都由 `resolveProductBehavior` 解析模式，并从同一个安装入口进入。

## 托管安装流水线

1. 用户点击“一键安装”。
2. 客户端检测产品是否已安装，并检测该产品声明的环境依赖。
3. 如果依赖缺失，暂停产品安装并只展示已批准的环境安装动作。
4. 依赖满足后，调用本地注册表中的安装适配器。
5. CLI 产品执行固定包部署；桌面产品下载固定来源的安装包。
6. 桌面安装包必须先通过本地签名、哈希或来源策略校验，再自动打开。
7. 安装结束后再次检测产品状态，记录安装凭据，并提供对应的安全卸载入口。

## 新厂商和新产品接入

新增目录内容时必须提供：

- 厂商 ID、产品 ID、名称、描述、类别、官网和教程地址。
- 产品类型、环境依赖、安装策略、下载与签名策略、卸载策略。
- Web 和教程类产品使用 `direct-open`。
- 未完成客户端审核的桌面产品使用 `official-installer-page`。
- 需要一键安装的产品必须增加客户端本地注册表条目和对应测试。

托管 CLI 还必须固定：

- 官方包名。
- 精确依赖列表。
- 允许的生命周期脚本和安装后验证命令。
- 安装凭据与卸载规则。

托管桌面产品还必须固定：

- 官方下载域名、路径和文件名。
- 预期发布者签名，必要时固定哈希。
- 已安装状态检测规则。
- 安全卸载规则。

## 安全边界

- 后台只能调整展示内容和已经批准的策略参数。
- 后台不能下发 EXE、Shell、PowerShell、CMD 或任意包名与命令。
- 后台目录不能单独把一个产品升级为托管安装。
- 只有同时存在于客户端本地注册表和本地下载/执行白名单中的产品才能自动安装。
- 注册表身份、厂商归属、产品类型、依赖和目录策略不一致时，客户端拒绝加载该目录。

## 生态资源安装

catalog schema v2 的 Skill、MCP 和插件位于顶层 `resources`，不再作为产品子目录。资源可以声明多个目标产品，但每个目标都必须独立引用客户端批准的 `moduleId + installProfileId`，并独立声明兼容性与能力。

资源出现在商店只代表可以浏览。用户点击安装后，客户端重新读取可信目录与本地目标状态，验证固定适配器和安装配置，展示将写入的目标与权限，再生成所有权收据。卸载只删除该收据拥有的文件和配置项，不清理用户手工安装的资源或设置。

后台、社区帖子和未来外部 AI 接口都只能引用资源 ID、版本和批准配置，不能提交任意包名、URL、命令、参数、配置片段或文件路径。
