# 客户端产品接入审批

AI Hub 将“后台展示目录”和“客户端本地执行许可”分开管理。后台可以新增、编辑、排序、启停厂商与产品，但不能因此获得本地安装、打开或卸载权限。

## 接入门槛

一个产品只有同时满足下列条件，才能进入客户端执行白名单：

1. 研究记录确认产品在 Windows 上的真实结构、官方来源、依赖、安装和卸载行为。
2. `shared/install-registry.cjs` 中存在固定的本地执行注册项。
3. 桌面安装包、CLI 包、运行时、签名、哈希、最终域名和完成证据均由客户端固定策略约束。
4. `shared/product-intake-approvals.cjs` 中存在独立审批记录，包含研究记录引用、审批时间和完整执行契约的 SHA-256。
5. `getProductIntakeDossier()` 能从注册项、下载策略和独立审批记录生成有效资料卡。

执行注册项或下载策略的任何字段发生变化，执行契约 SHA-256 都会变化；原审批自动失效，产品不能继续执行，直到重新研究并显式更新审批记录。注册项本身不能生成或批准自己的审批值。

## 审批资料卡

资料卡至少记录：

- 产品 ID 和架构类型；
- 官方来源；
- 产品运行组件；
- 安装、打开和卸载能力；
- 安装完成的可信证据；
- 独立研究记录引用、审批时间和执行契约 SHA-256。

伴侣型产品必须拆分 Windows Hub、专用 WSL 发行版、Gateway 服务和配对状态，不能把其中任意一层等同于整个产品已安装。

## 变更流程

后台候选只能进入默认停用的安全展示模块，不能直接获得执行权限。新增或调整可执行产品时，先更新研究记录，再修改本地执行注册项与策略，最后由独立审批记录确认新的契约 SHA-256，并运行 `tests/product-intake-dossier.test.cjs` 和全量发布门禁。
